Question: Open-Meteo licence page: the exact attribution text/format they ask for (CC BY 4.0), where it should be shown in an app,
and confirm the "current" forecast variables temperature_2m, weather_code, is_day (names and units) from the docs.

## Findings

Method note: pages were read through a summarising fetch tool, not by hand. Wording below is paraphrased except the one short quote.

### Attribution (official page https://open-meteo.com/en/licence)
- API data is licensed CC BY 4.0. Requirements: give appropriate credit, link to the licence, indicate whether changes were made; any reasonable way, but not implying Open-Meteo endorses you.
- Placement: show a link "next to any location Open-Meteo data are displayed" (that is the page's wording, as relayed).
- Example format: an HTML link to `https://open-meteo.com/` with the text "Weather data by Open-Meteo.com".
- Research citation is optional (APA example on the page, Zippenfenig 2023, Zenodo DOI 10.5281/ZENODO.7970649).
- The code on GitHub is AGPL v3 or later; that applies to software, not to API data. Upstream providers have their own licences (some CC BY-SA), listed on the page.
- Terms page https://open-meteo.com/en/terms: free API use means accepting CC BY 4.0, and free use is non-commercial only. The terms do not give attribution wording.
- Geocoding: the geocoding docs say location data is based on GeoNames (see R15.1).

### "current" variables (official docs https://open-meteo.com/en/docs)
- `temperature_2m`: degrees C by default; `temperature_unit=fahrenheit` converts.
- `weather_code`: WMO weather interpretation code (numeric).
- `is_day`: 1 = daylight, 0 = night (dimensionless).
- The `current` block returns each variable plus `time` and `interval` (seconds, e.g. 900 = 15 minutes).
- `current_units` is not documented on the docs page text I got (its JSON section describes only `hourly_units` and `daily_units`). Whether the API returns it in practice: UNVERIFIED.
- `timezone` defaults to GMT, `auto` resolves from the coordinates; `timeformat=unixtime` is available. Docs do not say explicitly that these rules apply to `current.time` (UNVERIFIED).

## Answer for Cuy
Show next to the weather (e.g. in the weather panel/tooltip) a link "Weather data by Open-Meteo.com" to https://open-meteo.com/, plus a link to the CC BY 4.0 licence (and GeoNames for city search); say if values are modified.
`current=temperature_2m,weather_code,is_day` is valid: degrees C, WMO code, 1/0 for day. Use `timezone=auto` and do not rely on `current_units`.
