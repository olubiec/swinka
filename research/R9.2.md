Question: Status of Phaser 4 in October 2026 (latest version, date) and of Phaser 3 (still receiving fixes?).
Main migration differences from v3 to v4 for a simple Arcade game. Is staying on 3.90 reasonable for a small offline project?

## Findings

Phaser 4 (sources: npm registry JSON for `phaser`, queried 2026-10-26; [phaser.io download page](https://phaser.io/download/phaser4); [v4.0.0 page](https://phaser.io/download/release/v4.0.0)):
- Latest on npm (`latest` tag): **4.2.1, published 2026-07-09** ("Giedi"), MIT licence. Registry "modified" is also 2026-07-09, so nothing newer as of today.
- History: 4.0.0 "Caladan" 2026-04-10 (after rc.7 on 2026-03-25), 4.1.0 2026-04-30 ([news](https://phaser.io/news/2026/04/phaser-4-1-0-salusa-release)), 4.2.0 2026-06-19 ([news](https://phaser.io/news/2026/06/phaser-v4-2-0-released)), 4.2.1 2026-07-09.

Phaser 3 (sources: npm registry, [Phaser archive](https://editor.phaser.io/download/archive), [3.90 announcement](https://phaser.io/news/2025/05/phaser-v390-released)):
- Newest 3.x on npm is **3.90.0, 2025-05-23**. No v3 release since (about 17 months). The 3.90 announcement calls it "likely the last version in the v3 tree".
- No official statement about v3 bug-fix backports or end of support found. Phaser's own post says there is "no reason to start on Phaser 3" for new projects ([Phaser 3 vs 4](https://phaser.io/news/2026/05/phaser-3-vs-phaser-4)), a recommendation, not a support policy. Treat v3 as effectively frozen (inference).

Migration v3 -> v4 ([official MIGRATION-GUIDE.md, 4.2.1 package](https://unpkg.com/phaser@4.2.1/changelog/v4/4.0/MIGRATION-GUIDE.md); [Phaser blog comparison](https://phaser.io/news/2026/05/phaser-3-vs-phaser-4)):
- Renderer: pipelines replaced by render nodes; FX and masks merged into one Filter system; BitmapMask -> Mask filter; lighting via `setLighting(true)`.
- Removed/changed: `Mesh`, `Plane`, `Geom.Point` (use Vector2), `Struct.Map/Set` (native), `Create.GenerateTexture`, `TextureManager.generate`, `phaser-ie9.js`, bundled Spine plugins, `setTintFill()` (use setTint + tint mode), `Math.TAU`. `roundPixels` default false (per-object `vertexRoundMode`). Canvas renderer "should be considered deprecated" (WebGL recommended). DynamicTexture/RenderTexture drawing now runs on `render()`. Compressed textures need Y-flip recompression.
- Phaser's blog says sprites, images, text, groups, cameras, tilemaps, input, Arcade and Matter physics, scenes, audio and tweens are "likely unchanged" and a typical game needs "a few hours" (vendor claim, not independently verified). The guide opened did not cover Arcade, tweens or animations specifically.

## Answer for Cuy
Phaser 4 is stable: 4.2.1 (2026-07-09), 4.0.0 shipped 2026-04-10. Phaser 3 stopped at 3.90.0 (2025-05-23); no support policy found.
For a small offline Arcade/Graphics/Text game, staying on a pinned local 3.90.0 is reasonable (nothing downloads at runtime; WebView2 is Chromium); migration looks cheap but is optional (inference).
If a future minigame needs Mesh/Plane or Spine, plan for v4 or avoid them; do not mix v3 and v4 across minigames.
