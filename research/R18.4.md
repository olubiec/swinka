Question:
R18.4 Smart App Control (SAC) and delivery channels (documented behaviour only, no bypass advice).
Use Microsoft Learn / support.microsoft.com.
1) Modes (Evaluation/On/Off) and the default on a new Windows 11 install in 2026.
2) Can SAC be turned back on after Off without reinstalling? Since which Windows build or update?
3) Does SAC or SmartScreen treat files without Mark-of-the-Web (copied by USB, LAN, cloud-synced folder) differently from downloaded ones? Does "Run anyway" apply only to files with MOTW?
4) Which common delivery channels (browser download of a zip, GitHub Release, USB stick, cloud link) leave MOTW on the extracted exe (Explorer extract vs 7-Zip)?
Answer for Cuy: which channel is documented as least likely to produce a hard block for an unsigned, unknown-reputation exe.

## Findings

Official Microsoft Learn / support pages were not reachable in this session. The points below come from third-party sources.

1) Modes and default (source kind: forum and tech press, not Microsoft)
- A forum guide (https://elevenforum.com/t/turn-on-or-off-smart-app-control-in-windows-11.4996/page-2) lists three states: Evaluation (blocks nothing, ends by switching itself on or off by device fit), On and Off.
- A tech-press article (https://windowslatest.com/2025/12/16/microsoft-confirms-you-can-soon-disable-smart-app-control-without-reinstalling-windows-11) says a clean install starts in evaluation for about a week; upgraded systems start off. The 2026 default is therefore reported only through the press, not confirmed by Microsoft.

2) Turn back on after Off (forum source)
- The forum page says re-enabling without a clean install works from builds 26100.8116 (24H2), 26200.8116 (25H2) and 2800.1896 (26H1), and that the change "is still rolling out".
- The tech-press article names Insider build 26220.7070 and says the change was expected in 2026.

3) Mark-of-the-Web (source kind: technical blog, textslashplain.com, 2026-04-28)
- https://textslashplain.com/2026/04/28/smart-app-control/
- SmartScreen AppRep checks the reputation of entry-point exes from an untrusted origin (MotW).
- SAC blocks certain file types (for example .bat, .js, .lnk, .vbs) from an untrusted origin; files without MotW are not subject to that block.
- SAC's check on loaded DLLs and scripts: the article does not say whether origin matters there.
- "Run anyway": the article does not mention it; for the file-type block the dialog offers no override.

4) Delivery channels
- Not researched. Which channels set MOTW on an extracted exe (browser zip, GitHub Release, USB, cloud link, Explorer vs 7-Zip): open.

## Answer for Cuy
The blog says SmartScreen acts on MotW-marked exes and that SAC's file-type block skips files without MotW (an .exe is not on that list).
This does not show that an unsigned .exe passes SAC without MotW; the code-check behaviour is unclear.
No delivery channel is documented here as least likely to block; this is open until Microsoft Learn is read.
