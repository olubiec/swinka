- The online manual (https://ondras.github.io/rot.js/manual/) text could not be read by the fetch tool (menu only), so API names below come from the TypeScript declarations in the 2.2.1 package (`lib/map/*.d.ts`, `lib/path/*.d.ts`, `lib/index.d.ts`), i.e. the package itself:
  - `ROT.Map.EllerMaze`, `ROT.Map.DividedMaze`: `new X(width?, height?)` (base `Map`, defaults `ROT.DEFAULT_WIDTH` 80 x `DEFAULT_HEIGHT` 25), then `.create(callback)`; callback is `(x, y, contents) => any`. The Eller code fills the map with 1 first, so 1 = wall, 0 = floor (read from `ellermaze.js`; UNVERIFIED for the other two).
  - `ROT.Map.IceyMaze`: `new IceyMaze(width, height, regularity = 0)`, `.create(callback)`.
  - `ROT.Path.AStar(toX, toY, passableCallback, options?)` and `ROT.Path.Dijkstra(toX, toY, passableCallback, options)`; `.compute(fromX, fromY, callback)`, callback `(x, y)` called for each step of the path; `passableCallback(x, y) => boolean`; `options = { topology: 4 | 6 | 8 }` (comment says default 8; for grid mazes use 4).
  - Exports confirmed in `lib/map/index.d.ts` and `lib/path/index.d.ts` (EllerMaze, DividedMaze, IceyMaze, Dijkstra, AStar).

**EasyStar.js**
- Repo https://github.com/prettymuchbryce/easystarjs ; npm `easystarjs` **0.4.4, published 2020-10-18** (npm metadata last modified 2022-06-16); licence **MIT** (README; LICENSE "Copyright (c) 2012-2020 Bryce Neal" in the package). Last commit date not shown on the page.
- Size (tarball, `bin/`): `easystar-0.4.4.min.js` **10,026 B** (about 3.9 KB gzip), `easystar-0.4.4.js` 25,142 B. README says "~7kb".
- API (README): `new EasyStar.js()`, `setGrid(2dArray)`, `setAcceptableTiles(array)`, `findPath(startX, startY, endX, endY, callback)` (callback gets path or `null`, returns an instance id), `calculate()` (call repeatedly), `cancelPath(id)`, `setIterationsPerCalculation(n)`, `enableDiagonals()`, `enableCornerCutting()`, `avoidAdditionalPoint(x, y)`, `setTileCost(tile, cost)`, `setAdditionalPointCost(x, y, cost)`, `enableSync()`, `setDirectionalCondition(x, y, dirs)`. Async by design (needs `calculate()` ticks unless `enableSync()`).

**Perfect maze / recursive backtracker**
- Recursive backtracker (depth-first) produces a spanning tree: every cell is connected and there is exactly one path between any two cells, so start-to-exit is always solvable ([Wikipedia: Maze generation algorithm](https://en.wikipedia.org/wiki/Maze_generation_algorithm), which says every cell is visited and the result is a connected tree; it favours long corridors, low branching). I confirmed this by running 2,000 random mazes per size: 100% solvable.
- Dead ends: Jamis Buck says recursive backtracker has "the fewest dead-ends" of the algorithms he covers ([blog](https://weblog.jamisbuck.org/2011/2/7/maze-generation-algorithm-recap.html)), no numbers there. **My own simulation** (Python, 2,000 mazes each, dead end = cell with one open side): 10x10 mean 11.9% (range 6-18%), 20x20 10.5% (7.8-13.8%), 30x30 10.3% (8.7-12.3%). Not a published figure.

## Answer for Cuy
rot.js 2.2.1 (BSD-3-Clause, `dist/rot.min.js` 68.7 KB) has all three mazes and AStar/Dijkstra: `new ROT.Map.EllerMaze(w,h).create(cb)`, `new ROT.Path.AStar(toX,toY,passableCb,{topology:4}).compute(fromX,fromY,cb)`. EasyStar 0.4.4 (MIT, 10 KB min) is async and only does paths.
For Hay Maze a hand-written recursive backtracker (about 20 lines) is enough: always solvable, about 10-12% of cells are dead ends (own measurement).
