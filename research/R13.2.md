Question: Open-source C# implementations of "pause when a fullscreen app is running": Lively Wallpaper, PowerToys, Flow Launcher,
Rainmeter plugins, others. For each: file URL, licence, and how the check differs from Chromium's fullscreen_win.cc
(window rect equals monitor rect + no WS_THICKFRAME/WS_DLGFRAME). Note any handling of the desktop shell windows (Progman, WorkerW).

## Findings

Method note: pages were read through a summarising fetch tool, not opened by hand. Descriptions of code are as reported by it.

### Reference: Chromium
[ui/base/fullscreen_win.cc](https://chromium.googlesource.com/chromium/src/+/main/ui/base/fullscreen_win.cc) (C++; BSD per our "Już sprawdzone" table, licence file not re-opened).
Three checks: SHQueryUserNotificationState (D3D or PRESENTATION_MODE), window geometry, console fullscreen.
Geometry: foreground window, primary monitor only, `IntersectRect` + `EqualRect` with the monitor rect (window may be larger), rejects WS_DLGFRAME, WS_THICKFRAME, WS_EX_WINDOWEDGE, WS_EX_TOOLWINDOW.
No special case for Progman/WorkerW.

### Flow Launcher (C#, the closest match)
- File: [Flow.Launcher.Infrastructure/Win32Helper.cs](https://github.com/Flow-Launcher/Flow.Launcher/blob/dev/Flow.Launcher.Infrastructure/Win32Helper.cs), method `IsForegroundWindowFullscreen()`. Read from the raw file on branch dev.
- Licence: UNVERIFIED (believed MIT, LICENSE file not opened).
- Logic: foreground window; false if desktop/shell window (`GetDesktopWindow`/`GetShellWindow`); false for class `Flip3D`; special case for `ConsoleWindowClass`;
  for `Progman`/`WorkerW` it looks for a `SHELLDLL_DefView` child with a `SysListView32` "FolderView" child and returns false if found; then width and height must equal the nearest monitor's `Bounds`
  (position NOT compared). No SHQueryUserNotificationState, no style flags.
- Difference from Chromium: handles the desktop (Progman/WorkerW) explicitly, which is exactly Cuy's known bug; no WS_THICKFRAME test; size must be equal (not just covering); works for any monitor, not only primary.

### PowerToys (C++, not C#)
- [src/common/utils/game_mode.h](https://github.com/microsoft/PowerToys/blob/main/src/common/utils/game_mode.h), licence MIT (first line of root LICENSE confirmed).
- Only `SHQueryUserNotificationState == QUNS_RUNNING_D3D_FULL_SCREEN`. No window checks, no desktop handling.

### Lively Wallpaper (C#)
- Licence: UNVERIFIED (believed GPL-3.0; so pattern only).
- Source file with the check: not found. The repo tree listing I got was truncated. Layout seen: `src/Lively/Lively.Models/Enums/ProcessMonitorAlgorithm.cs`, `PlaybackPolicy.cs`.
- Behaviour per [wiki Performance](https://github.com/rocksdanister/lively/wiki/Performance): default "Grid" algorithm splits the screen into tiles and checks window coverage (default threshold 95%, `ProcessMonitorGridTileCoverageThreshold`);
  other modes: All Process, Foreground Process, Direct3D (exclusive fullscreen only).
- [Issue #474](https://github.com/rocksdanister/lively/issues/474): maintainer describes a 50x50 tile grid checked against all top-level windows; "no window means desktop". Progman/WorkerW not mentioned. Reported problems are false negatives (maximised Firefox, multi-monitor), not false positives.

## Answer for Cuy
Best pattern to copy is Flow Launcher's `IsForegroundWindowFullscreen()` (C#): skip GetDesktopWindow/GetShellWindow and Progman/WorkerW that host the icon list, then compare size to the monitor.
Combine it with Chromium's D3D/presentation state check and the style flags. PowerToys only checks D3D. Lively's grid is the heavy option and its licence is unconfirmed (use as idea only).
