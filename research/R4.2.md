Question: SignPath Foundation free code signing for open-source projects: requirements (licence, public repo, CI build,
project activity), how to apply, typical waiting time, and whether a hobby project (desktop pet, MIT) qualifies.

## Findings

**Requirements** (source: SignPath Foundation terms, https://signpath.org/terms)
- Licence: OSI-approved open source licence, "without commercial dual-licensing", for all components. MIT qualifies on this point.
- Source: the signed binary must trace back to a specific source repository. The page does not explicitly say "public repository".
- Build: binaries must be built from source in a verifiable way; build scripts and CI configuration count as source code. SignPath's open-source page says the build must be fully automated and integrated, so the binary comes directly from the repo. https://about.signpath.io/product/open-source
- Activity: the project must be actively maintained and already released in the form to be signed.
- Also: no malware or potentially unwanted programs; documented function; published code signing policy; multi-factor authentication for all team members; defined author, reviewer and approver roles; manual approval for each signing release.
- Reputation: executable programs need "a certain verifiable reputation" (not required for libraries/packages); the Foundation may decline projects. (terms page; the threshold is not defined)

**How to apply**
- Form at https://signpath.org/apply (linked from https://signpath.org/). The home page says OSS services are free and no personal identification is needed; the private key is kept on SignPath's HSM.
- Third-party account of a one-person project (blog, not official): public repo, LICENSE file, README, code signing policy and CODE_OF_CONDUCT prepared before applying; form asks repo URL, licence, download URL, description; follow-ups by email. https://zenn.dev/shm_7ec/articles/signpath-oss-code-signing?locale=en

**Waiting time**
- Not stated by SignPath; the blog above was written while the application was still pending. No figure found.

**Does a hobby MIT desktop pet qualify**
- Licence and CI requirements can be met (MIT, GitHub Actions build, public Releases). The risks: the "verifiable reputation" requirement for executables, activity/maintenance, and the Foundation's right to decline. The page does not address hobby projects. (UNVERIFIED whether a new project with few users is accepted.)
- Repo consequence: a unique signed build needs a CI build and a signing policy page in the repo; MFA for the team members.

## Answer for Cuy
SignPath Foundation is free for OSS: OSI licence (MIT fine), build from the repo in CI, active project, a code signing policy, MFA, manual release approval.
Apply at signpath.org/apply; waiting time is not published.
A hobby MIT project meets the formal points, but the "verifiable reputation" rule for executables may be a hurdle for a brand-new project (UNVERIFIED).
