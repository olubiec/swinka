Question: NAudio breaking changes from 1.8.4 to 2.2.1 that affect: WaveOutEvent, WaveFileReader, AudioFileReader,
SampleChannel / VolumeSampleProvider, SmbPitchShiftingSampleProvider, MMDeviceEnumerator/MMDevice (IDisposable).
Use the NAudio GitHub releases, CHANGELOG/RELEASE_NOTES and the "upgrading to NAudio 2" notes.

## Findings

Method: I checked out the tags `v1.8.4` and `v2.2.1` of https://github.com/naudio/NAudio and diffed the named classes
(whitespace ignored). Source of every code fact below = GitHub source at those tags. Licence: MIT since 2.0.0
(https://github.com/naudio/NAudio/releases, release page v2.0.0). Latest 2.x = 2.2.1 (4 Sep 2023, tag commit date; RELEASE_NOTES).

**No "upgrading to NAudio 2" document exists.** `Docs/` at v2.2.1 has no such file and RELEASE_NOTES.md has no 2.0.0 section.
The GitHub release page for v2.0.0 only lists: split into satellite assemblies, MIT licence, .NET 3.5 dropped, strong naming
(https://github.com/naudio/NAudio/releases). The closest "upgrade" text is the author's 2021 plan post
(blog post, plan not final): https://markheath.net/post/naudio-2-plans - says NAudio 2 is meant to be highly backward compatible,
minimum .NET Framework 4.7.2, top-level NAudio package still references all satellite packages.

**Changes that matter for a .NET Framework 4.8 app (all from RELEASE_NOTES.md at v2.2.1:
https://github.com/naudio/NAudio/blob/v2.2.1/RELEASE_NOTES.md):**
- 2.0.0: split into assemblies (Core, WinMM, Wasapi, Asio, Midi, WinForms + umbrella NAudio), strong-named, .NET 3.5 dropped.
  Namespaces of the classes below did NOT change (`NAudio.Wave`, `NAudio.Wave.SampleProviders`, `NAudio.CoreAudioApi`), so code recompiles, but the DLLs are different.
- 2.1: `AudioFileReader` uses `MediaFoundationReader` for MP3 by default; `IWavePlayer` gets `OuputWaveFormat` (sic, typo is in the notes).
- 2.2: WASAPI uses background threads; WASAPI stop improvements; `ComImport` added to CoreAudioApi interfaces.

**Gotcha:** `AudioSessionManager` has a public `Dispose()` in both versions, but its class declaration is NOT `: IDisposable`
in either ([v2.2.1 line 18](https://github.com/naudio/NAudio/blob/v2.2.1/NAudio.Wasapi/CoreAudioApi/AudioSessionManager.cs#L18)),
so `using (var m = device.AudioSessionManager)` will not compile; dispose the `MMDevice` instead (it disposes the manager).
`AudioSessionControl` is `IDisposable` in both.

**Newer line exists:** NAudio's `main` branch has already moved on (it has a `src/` layout and the file list differs from the 2.2.1 tag),
and a search listed NAudio.Core 3.0.0 on NuGet (https://packages.nuget.org/packages/NAudio.Core/3.0.0, not opened). This note is about 2.2.1 only.

## Answer for Cuy
Upgrade is source-compatible for all six classes (same namespaces, same public API); what changes is the DLL set (Core + WinMM + Wasapi + umbrella NAudio).
Only behaviour changes: `WaveOutEvent.Volume` reads the real device volume; `AudioFileReader` decodes MP3 via Media Foundation.
`MMDevice` and `MMDeviceEnumerator` are `IDisposable` (dispose them); `AudioSessionManager` is not declared `IDisposable`, so no `using` on it.
There is no official upgrade guide, only the release notes above.
