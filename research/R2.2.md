Question: For short retro sound effects in a browser page compare ZzFX, jsfxr (sfxr.me), and a plain Web Audio oscillator approach:
licence, size, sound quality/variety, whether sounds can be generated at runtime from parameters (no audio files).
Cite forum or blog comparisons (js13kGames, r/gamedev, html5gamedevs) where possible.

## Findings

| | ZzFX | jsfxr (sfxr.me) | Plain Web Audio oscillator |
| --- | --- | --- | --- |
| Licence | MIT | package ships an UNLICENSE file (public-domain style text, "free and unencumbered software released into the public domain"); npm licence field is empty | none (your own code) |
| Size | ZzFXMicro.min.js 1,226 bytes (npm 1.4.0 tarball) | sfxr.js 35,898 + riffwave.js 5,447 bytes, unminified (npm 1.4.1 tarball) | a few lines, your own |
| Runtime from parameters | yes, `zzfx(...params)` with 20 parameters | yes, the library generates and plays sounds in code (README) | yes |
| Variety | one parameter set designed in a web tool (https://killedbyapixel.github.io/ZzFX) | the sfxr generator (https://sfxr.me) | whatever you code |

- ZzFX: README https://www.npmjs.com/package/zzfx ("Less than 1 kilobyte when compressed", "No sound asset files", made for size-limited jams like JS13K). Source: npm README.
- jsfxr: maintained by Chris McCormick at https://github.com/chr15m/jsfxr (npm jsfxr 1.4.1, published 2026-05-05); a port of sfxr by Eric Fredricksen. README shows `import { sfxr } from "jsfxr"` and browser script tags `https://sfxr.me/riffwave.js` and `https://sfxr.me/sfxr.js`. Source: npm tarball and README (https://www.npmjs.com/package/jsfxr). An older fork, gheja/jsfxr, was found in an earlier search; it is a different repo and not used here.
- Blog: Jack Rugile, "Arcade audio for js13k games" (CodePen, 2014-08-14, https://codepen.io/jackrugile/post/arcade-audio-for-js13k-games): jsfxr is about 2,517 bytes with Closure Advanced mode, and generating sounds in code beats shipping audio files under a size limit. It does not judge sound quality or discuss Web Audio oscillators.
- Plain oscillator: Chrome's autoplay rules apply to any AudioContext, which starts suspended until a user gesture (https://developer.chrome.com/blog/autoplay). The same is true for ZzFX, which creates its own AudioContext.
- No forum comparison of ZzFX vs jsfxr sound quality was found (js13kGames, r/gamedev, html5gamedevs were not found in searches).

## Answer for Cuy
ZzFX (MIT, 1,226 bytes) and jsfxr (public-domain UNLICENSE file, about 41 KB unminified) both build sounds at runtime from parameters; a bare oscillator needs the most code of your own.
ZzFX is by far the smallest and already planned; jsfxr needs its licence text read before shipping.
No quality comparison from forums was found, so judge by ear in the two web designers.
