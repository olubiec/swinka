Question: How can a Windows app tell music playback from a voice call (Discord, Teams, Zoom, WhatsApp)? Do these apps use
the eCommunications role or a separate audio category that is visible per session? List process names of popular call apps
to exclude. Sources: Microsoft docs on audio roles/ducking, forum threads.

## Findings

**The eCommunications role is user-assigned and not a per-session label.**
Windows 7+ lets the user pick a separate "communication device"; the user, not the app, controls which device holds the role, and the OS treats any stream opened on that device as a communication stream
(Microsoft Learn, official: https://learn.microsoft.com/en-us/windows/win32/coreaudio/using-the-communication-device).
The page does not say a session's role is visible to other apps. If the user has one device for everything, the role tells you nothing.

**Stream categories exist but are not exposed per session.**
`AUDIO_STREAM_CATEGORY` has `Communications`, `GameChat` (does not attenuate other streams), `Media`, `Movie`, `GameMedia` and others; the page does not say a category can be read by another process
(official: https://learn.microsoft.com/en-us/windows/win32/api/audiosessiontypes/ne-audiosessiontypes-audio_stream_category).
NAudio 2.2.1 reflects this: `AudioStreamCategory` is used only when initialising your own stream (`AudioClientProperties.eCategory`), and `AudioSessionControl` has no category member
(public members: AudioMeterInformation, SimpleAudioVolume, State, DisplayName, IconPath, GetSessionIdentifier, GetSessionInstanceIdentifier, GetProcessID, IsSystemSoundsSession, GetGroupingParam
- [AudioSessionControl.cs](https://github.com/naudio/NAudio/blob/v2.2.1/NAudio.Wasapi/CoreAudioApi/AudioSessionControl.cs)).
I found no Microsoft page that says Discord, Teams, Zoom or WhatsApp use the communications role or category; Discord's own attenuation setting lowers other apps during calls, and Windows has a separate communications ducking option
("Do nothing" in Sound > Communications) - third-party article: https://www.guidingtech.com/stop-discord-from-lowering-app-volume-on-windows/ .

**What the docs do give you:**
- Sessions are per endpoint and cannot mix capture and render streams (https://learn.microsoft.com/en-us/windows/win32/coreaudio/audio-sessions). A call app therefore has a render session AND a capture (microphone) session, usually with the same process id.
  Idea (UNVERIFIED, my inference): treat a process as "in a call" when it has an Active render session and an Active capture session on `DataFlow.Capture`; browser tabs with a microphone would also match.
- Matching on `Process.GetProcessById(GetProcessID).ProcessName` works (sample: https://learn.microsoft.com/en-au/answers/questions/1691452/how-to-check-if-an-audio-file-is-being-played-by-p).

**Process names to exclude - NOT verified, no source found:** Discord (`Discord`), Zoom (`Zoom`), Microsoft Teams (`ms-teams`, classic `Teams`), WhatsApp (`WhatsApp`), Skype (`Skype`), Slack (`slack`), Webex. These are my recollection - UNVERIFIED, check in Task Manager on the real PC. Web calls (Meet, Teams in a browser) run inside the browser process and cannot be told apart by name.

## Answer for Cuy
There is no documented per-session flag for "voice call", and no source says Discord/Teams/Zoom/WhatsApp use eCommunications, so rely on a process-name exclude list (names UNVERIFIED) plus, optionally, "same process also has an active microphone session".
The default role/communications device is the user's choice, so it cannot separate music from calls.
Browser-based calls cannot be excluded by name.
