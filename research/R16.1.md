Question:
R16.1 Prior art for "mouse shake" detection.
Our MouseShakeDetector (Cuy.Core) counts a shake as: at least 6 horizontal direction reversals within 1.0 s, average speed above 900 px/s, cursor within 300 px of the pig, 2 s debounce, steps under 4 px ignored. These numbers come from our own draft, not from a source.
a) PowerToys "Find My Mouse" has a shake activation (docs: https://microsoft.github.io/PowerToys/modules/mouseutils/findmymouse/). Find its source in github.com/microsoft/PowerToys (UNVERIFIED hint: under src/modules/MouseUtils/FindMyMouse). Describe the algorithm in plain words (what is measured, sampling, window length, direction-change or distance criteria) and list every numeric constant with a permalink to a tagged release. Licence is MIT: say so with the LICENSE link.
b) Up to 2 other open-source shake/wiggle detectors (Windows tools, macOS shake-to-locate clones, KWin/GNOME shake-cursor effect), same details.
c) For each: how does it avoid false positives while the user drags a window or file (mouse button state?) and on high-DPI or multi-monitor setups?
d) Table: our values vs PowerToys vs others. Say which of our numbers has no support in any source.

## Findings

### a) PowerToys Find My Mouse (source kind: official Microsoft docs)
- The official docs page https://microsoft.github.io/PowerToys/modules/mouseutils/findmymouse/ mentions the shake only in passing: mouse events "trigger sonar animations (e.g., after a shake or shortcut)". It gives no algorithm, no thresholds, no time window, and says nothing about turning shake off separately. The page also describes a double-press of Ctrl as the detailed activation path.
- Source code (github.com/microsoft/PowerToys, MouseUtils/FindMyMouse): NOT OPENED. The GitHub page was not reachable in this session, so no algorithm description, no constants and no permalink. The UNVERIFIED path hint was not checked.
- Licence MIT: NOT VERIFIED in this session (LICENSE file not opened).

### b) Other detectors (source kind: issue tracker, not code)
- KDE issue https://invent.kde.org/plasma/kwin/-/issues/197 (KWin) refers to an existing "Shake Cursor" option next to "Track Mouse" and asks that the Spotlight effect be added to Shake Cursor. The issue states no thresholds and does not describe the shake mechanism. The KWin source was not opened.
- No other open-source shake/wiggle detector (Windows tool, macOS clone, GNOME) was found with usable detail.

## Answer for Cuy
No source read here gives shake constants, so none of our five numbers can be cited as sourced. Keep them as draft defaults, marked "not sourced", and tune them by hand on the PC.
Before using PowerToys as a pattern, read its FindMyMouse source at a tagged release (not checked here).
Do not copy code; MIT allows it, but the algorithm has not been read.
