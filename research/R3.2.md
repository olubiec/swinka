Question: After installing with a Velopack Setup.exe on Windows: what is the install folder and the path of the main exe
(e.g. %LocalAppData%\<packId>\current\...)? Does that path stay the same across updates? What should a "start with Windows"
entry in HKCU\Software\Microsoft\Windows\CurrentVersion\Run point to (the exe in "current", a stub, or Update.exe)?
Does Velopack create Start menu / desktop shortcuts by default and how to configure it (vpk options)?

## Findings

**Install folder and layout** (source: official docs)
- Per-user Setup.exe installs to `%LocalAppData%\{packId}` by default; override at install time with `Setup.exe --installto {dir}`. https://docs.velopack.io/packaging/operating-systems/windows
- `current\` holds the app files (YourApp.exe, DLLs, sq.version). On update the whole `current` folder is replaced, so settings and logs must live elsewhere. (same page)
- `Update.exe` sits in `{packId}\` next to `current`. (same page)
- A small stub `YourApp.exe` sits at the root of `{packId}\` and launches the real exe inside `current`. Created by both Setup.exe and MSI, so shortcuts and launchers can point to a stable path. (same page)

**Does the path stay the same across updates**
- Yes: the install root stays; only `current` is replaced, and the root stub gives a path that "survives updates". (same page)
- Exception seen for portable packages: issue #982 (2026-07-06, closed) reports the entry exe name changed from --packTitle to --mainExe after an update. Not about Setup.exe installs. https://github.com/velopack/velopack/issues/982

**What the Run key should point to**
- The docs do not cover autostart. Candidate: the root stub `%LocalAppData%\{packId}\<stub>.exe`, because the docs describe it as the stable launch path. UNVERIFIED: the stub file name (the docs write "YourApp.exe") and whether it matches `--mainExe`.
- Do not point to `Update.exe` (it is the updater, not the app; no source recommends it for autostart).
- Alternative inside Velopack: `--shortcuts` accepts a `Startup` location. https://docs.velopack.io/integrating/shortcuts

**Shortcuts**
- Default `vpk pack --shortcuts` is `Desktop,StartMenuRoot`. https://docs.velopack.io/reference/cli/content/vpk-windows
- Values: `Desktop`, `StartMenuRoot`, `StartMenu` (subfolder; also needs `--packAuthors`), `Startup`, `None`. Names come from `--packTitle`. Shortcuts are removed on uninstall. https://docs.velopack.io/integrating/shortcuts
- Runtime alternative: `new Shortcuts().CreateShortcutForThisExe(ShortcutLocation.Desktop)` in `OnAfterInstallFastCallback`; the page marks these classes as legacy. (same page)
- Known issue: #253, net48 app on some machines (suspected VMs) did not get shortcuts; closed as bug, workaround is creating them in code. https://github.com/velopack/velopack/issues/253

## Answer for Cuy
Install root is `%LocalAppData%\{packId}`; the app is in `current\`, and the root stub exe launches it. The root path survives updates, `current\` is replaced.
Point the HKCU Run entry at the root stub (inference from the docs, UNVERIFIED); never at Update.exe. Or use `--shortcuts ...,Startup`.
Shortcuts: Desktop + Start menu root by default; change with `vpk pack --shortcuts <list>` (`None` disables).
