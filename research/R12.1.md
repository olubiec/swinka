Question: Windows per-session peak meters (IAudioMeterInformation on IAudioSessionControl, e.g. via NAudio): do they report
non-zero levels for Spotify desktop, Chrome/Edge playing YouTube, Discord, games, VLC? Known problems: one session for all
browser tabs, apps in WASAPI exclusive mode, Bluetooth headphones, muted session. StackOverflow / GitHub issue links.

## Findings

**Short version: the mechanism is documented, but I found no source that tests those specific apps.** Per-app results below are marked accordingly.

**How session meters work (Microsoft docs + one working sample):**
- Each session is one process by default (`GUID_NULL` session = one per process); cross-process sessions and grouping parameters can merge streams
  (Microsoft Learn, official: https://learn.microsoft.com/en-us/windows/win32/coreaudio/audio-sessions , https://learn.microsoft.com/en-us/windows/win32/coreaudio/grouping-parameters).
- A session is Active while a stream runs, Inactive afterwards, then Expired (same audio-sessions page). Filtering on `State == Active` is therefore valid.
- A community answer on Microsoft Q&A uses NAudio `AudioSessionManager.Sessions` + `AudioMeterInformation.MasterPeakValue` + `GetProcessID` and says nonzero = process is producing sound;
  the peak is instantaneous, so a 0 can occur during silence in a track and you must poll repeatedly
  (forum answer: https://learn.microsoft.com/en-au/answers/questions/1691452/how-to-check-if-an-audio-file-is-being-played-by-p).
- Matthew van Eerde (Microsoft audio engineer's blog) reads a per-session peak for active sessions and notes there is no API to enumerate streams inside a session
  (blog: https://matthewvaneerde.wordpress.com/2013/09/26/getting-peak-meters-and-volume-settings-for-all-apps-and-audio-devices-on-the-system/).

**Browsers - one session for all tabs: CONFIRMED for the mixer, inferred for the API.**
Chrome and Edge show as a single entry in the Windows 10 volume mixer, every tab grouped under the browser name
(news article, 2021: https://www.windowslatest.com/2021/05/21/microsoft-edge-chrome-to-get-windows-10-audio-settings-integration/amp/ ; it describes a planned per-tab change, current status UNVERIFIED).
Chromium's audio service runs out of process on Windows (official README: https://chromium.googlesource.com/chromium/src/+/lkgr-android-internal/services/audio/README.md),
so the session probably belongs to that helper process, not to a tab process - UNVERIFIED inference, test with `GetProcessID`.
Consequence: a nonzero peak says "the browser is making sound", never which tab, and not YouTube vs any other page.

**WASAPI exclusive mode:** the software peak meter always returns 0.0 in exclusive mode; a device with a hardware meter can still report
(Microsoft Learn, written for the endpoint meter: https://learn.microsoft.com/en-us/windows/win32/coreaudio/peak-meters). Exclusive mode also silences every other app on that endpoint
and session volume interfaces have no effect on it (https://learn.microsoft.com/en-us/windows/win32/coreaudio/exclusive-mode-streams). So an exclusive-mode player shows zero or no session - expected for audiophile setups, rare for Spotify/YouTube/games.

**Spotify:** only third-party evidence of session use: a Pycaw article detects Spotify via its session volume and the executable name `Spotify.exe`, with the caveat that muted sessions confuse the check
(https://gurubase.io/g/python/detecting-spotify-audio-playback-state-with-pycaw). No peak-meter test found. UNVERIFIED that peak > 0 while playing.

**Muted session:** whether a muted session still reports a peak is not stated in any page I opened. The endpoint doc says the endpoint meter reads before endpoint volume/mute attenuation
(Microsoft Learn, IAudioMeterInformation page), which suggests peaks continue - only an inference for sessions, UNVERIFIED.

**Bluetooth headphones:** nothing found. The Microsoft peak-meter page says hardware meters exist only on some devices and software metering applies otherwise (shared mode), implying the meter works at the engine level regardless of transport - UNVERIFIED.

**Discord, games, VLC:** no source found for their session or peak behaviour. Games using exclusive mode would read 0.0 (see above).

## Answer for Cuy
Session peak meters are a valid "something is audible from process X" signal via `State == Active` and `MasterPeakValue` above a small threshold (tune by testing; no documented value).
Browsers appear as one session (all tabs/YouTube indistinguishable); exclusive-mode apps read 0.0 or are invisible; muted/Bluetooth behaviour is undocumented.
No source tests Spotify, Discord, VLC or games - needs a manual test on the target PC before F6-01 relies on it.
Poll repeatedly (peak is instantaneous) and wrap each read in try/catch.
