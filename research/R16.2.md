## Findings

### a) GetMouseMovePointsEx (source kind: Microsoft Learn, official; page opened)
https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getmousemovepointsex
- Signature: `int GetMouseMovePointsEx(UINT cbSize, LPMOUSEMOVEPOINT lppt, LPMOUSEMOVEPOINT lpptBuf, int nBufPoints, DWORD resolution);`
- Purpose per page: it "retrieves a history of up to 64 previous coordinates of the mouse or pen". The system retains the last 64 coordinates and their time stamps.
- `resolution`: GMMP_USE_DISPLAY_POINTS (1) for display resolution; GMMP_USE_HIGH_RESOLUTION_POINTS (2) for a 0–65,535 range, which the page links to absolute pointing devices.
- Return value: the number of points in the buffer, or -1 on failure (GetLastError).
- Input point must be in screen coordinates. With multiple monitors the function "may fail or return erroneous values" for negative coordinates; the page's fix is to use the SM_*VIRTUALSCREEN metrics.
- Minimum client Windows 2000 Professional (desktop apps only); library User32.lib; DLL User32.dll.
- The page does not discuss DPI scaling directly.
- The MOUSEMOVEPOINT structure fields were NOT read (linked page not opened). The timestamp field is mentioned but its layout is UNVERIFIED.
- .NET Framework 4.8 via P/Invoke: the signature uses only plain integer, pointer and DWORD types, so a P/Invoke is plausible; NOT VERIFIED against a .NET source.

## Answer for Cuy
GetMouseMovePointsEx returns up to 64 recent points with time stamps, which could replace 33 ms polling for shake detection; it is available since Windows 2000 (Microsoft Learn).
Multi-monitor negative coordinates need the virtual-screen metrics; check this on the PC before using it.
The MOUSEMOVEPOINT layout and a .NET P/Invoke sample are not verified.
