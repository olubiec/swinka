Question: Open-Meteo geocoding API (geocoding-api.open-meteo.com/v1/search): does language=pl return Polish names
(e.g. "Warszawa", "Kraków")? How are ambiguous names handled (e.g. "Nowa Wieś") - ordering by population? Which fields exist
(admin1..admin4, country_code, population, timezone)? Official docs link.

## Findings

Method note: the official docs page was read through a summarising fetch tool. I could not run live requests (the shell cannot reach other sites), so no example response was checked.
Official docs: https://open-meteo.com/en/docs/geocoding-api (official docs)

### Polish names
- `language` (default `en`, lowercase) localises `name`, `country`, `admin1` to `admin4` and localised qualifiers in `name`. Translated names are returned "when available", otherwise it falls back to English or the native name.
- Whether `language=pl` gives "Warszawa" and "Kraków" specifically: UNVERIFIED (docs give no examples for Polish; no live call made).

### Search and ambiguity
- Parameters: `name` (required), `count` (default 10, max 100), `format` (json or protobuf), `language`, `countryCode` (ISO 3166-1 alpha-2, e.g. `PL`), `apikey` (commercial only).
- `name`: 2 characters = exact match; 3+ characters = normalised prefix match, case- and diacritic-insensitive, must match the start of an indexed name. Empty or 1-character searches return nothing.
- Qualifier after a comma ("Nowa Wieś, Mazowieckie"): must match exactly (country name, 2-letter code, admin1 name or abbreviation). No partial matching. Only text between the first and second comma is used.
  `countryCode` is the unambiguous filter, and filters are applied before `count`.
- Ordering: NOT described in the docs. Ordering by population is UNVERIFIED. The `population` field exists, so the client can sort itself.

### Response fields (`results` array; empty fields may be omitted)
`id`, `name`, `latitude`, `longitude`, `elevation`, `timezone` (tz database), `feature_code` (GeoNames), `country_code`, `country`, `country_id`, `population`, `postcodes` (array),
`admin1`..`admin4` (+ `admin1_id`..`admin4_id`). The docs example shows `admin2` as an empty string while saying empty fields are omitted, so handle both missing and empty.
A location can be fetched by ID: `https://geocoding-api.open-meteo.com/v1/get?id=<ID>`. Errors: HTTP 400 with `"error": true` and `reason`.
Attribution on the page: location data is based on GeoNames.

## Answer for Cuy
`language=pl` is documented to localise name, country and admin1-4 when a translation exists (fallback English/native); "Warszawa" and "Kraków" not confirmed by a live call.
Ordering of ambiguous names is not documented: send `countryCode=PL`, request `count` of about 10 and let her pick (show name + admin1 + admin2, use `population` only as a tie-break).
Fields: id, name, lat/lon, elevation, timezone, country_code, population, admin1..admin4, postcodes. Credit GeoNames.
