Question: Which Windows API patterns in C# desktop apps commonly cause antivirus false positives (SetWinEventHook,
EnumWindows, HKCU Run key autostart, global mouse polling, single-file packers, unsigned exe)? Cite StackOverflow,
Microsoft Q&A or vendor forum threads. List practical mitigations for a hobby app.

## Findings

**Hooks (SetWindowsHookEx, global hooks)**
- Microsoft Q&A: Veracode flagged `SetWindowsHookEx` as embedded malicious code (CWE-506). Microsoft answer: hooking is flagged because DLL injection is a common rootkit technique, though it has legitimate uses. Another answer: a global hook injects its DLL into almost all other processes, which is what the scanner sees. No fix confirmed in the thread. https://learn.microsoft.com/en-us/answers/questions/1693583/veracode-error-with-setwindowshookex-win-api-call
- TrustedSec: `SetWindowsHookEx` can log keystrokes or inject code, "has been detected by multiple Security Products". https://trustedsec.com/blog/putting-our-hooks-into-windows
- AltDrag (hooks mouse and keyboard to move windows): installer flagged "Generic.ml" by Palo Alto in 2021; reversed after a vendor review. https://live.paloaltonetworks.com/t5/virustotal/virustotal-false-positive-on-altdrag-1-45-software/m-p/416794
- SetWinEventHook: no thread found (not mentioned in the TrustedSec article).

**Unsigned / generic C# detections**
- Microsoft Q&A (Visual Studio 2022 C# project flagged Gen:Variant.MSILHeracles by Bitdefender); another poster's C# WinForms exe was flagged the same on VirusTotal, so generic signatures hit ordinary .NET programs. Answers: scan with a second product, submit the file to the vendor, add an exclusion for the project folder. https://learn.microsoft.com/en-us/answers/questions/1084016/visual-studio-2022-c-generates-gen-variant-msilher
- B4X forum: unsigned executables are often flagged; newly signed ones can be too; flags usually clear within days. https://www.b4x.com/android/forum/threads/trojan-win32-wacatac-h-ml.142683/
- Velopack docs: "unsigned applications are frequently flagged by SmartScreen and antivirus". https://docs.velopack.io/packaging/signing

**Packers / obfuscators**
- Red Gate forum: a .NET exe protected with SmartAssembly 8.0 was flagged Trojan:Win32/Wacatac.B!ml while other exes were not; reply says obfuscators are periodically caught by detection patterns; advice: submit to Microsoft, wait for pattern updates, test other scanners. https://productsupport.red-gate.com/hc/en-us/community/posts/24975042297757-Microsoft-Defender-and-other-Anti-Virus-software-detect-trojan-win32-wacatac-b-ml-and-other-threats

**Not found as a thread**
- EnumWindows, HKCU Run key autostart and global mouse polling (GetCursorPos): no StackOverflow, Microsoft Q&A or vendor thread found that ties these to detections. A search surfaced EDR detection rules for Run-key changes (e.g. detection.fyi sigma pages), which are not AV false-positive reports and were not opened.

**Mitigations for a hobby app (from the sources, plus inference)**
1. Do not obfuscate or pack the exe (Red Gate thread).
2. Avoid DLL-injecting global hooks; if input is only needed in your own window, use window messages (suggestion from the Q&A summary, not stated in the thread). A low-level hook running in-process is another option (UNVERIFIED).
3. Sign the exe (SignPath Foundation or other, see R4.1/R4.2); signing is not a guarantee (B4X).
4. Scan each release on VirusTotal before publishing; submit detections to the vendor and to Microsoft (https://www.microsoft.com/en-us/wdsi/filesubmission).
5. Publish source and checksums; explain in the README which features trigger warnings (inference).

## Answer for Cuy
Best-evidenced triggers: global hooks (SetWindowsHookEx), obfuscators/packers, and plain unsigned .NET exes with generic signatures.
No threads found for EnumWindows, Run-key autostart or mouse polling (UNVERIFIED as triggers).
Mitigate: no packer/obfuscator, avoid injecting hooks, sign if possible, check VirusTotal, submit false positives to Microsoft and the vendor.
