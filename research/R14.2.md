Question: In eSheep/DesktopPet (C#): how do child animations (<childs> in animations.xml) and multiple pets work in the code
(StartUp / FormPet, AddSheep, max pets)? Give file and method names with links. Can two pets interact, or only spawn children?

## Findings

Method note: the three source files were read through a summarising fetch tool (raw files on master), not by hand. Method names are as reported; line numbers not confirmed.
Licence: MIT (LICENSE.md, per repo page). Desktop app is in `src/dotNet/`, README says compiled with .NET 4.7. https://github.com/Adrianotiger/desktopPet

### Multiple pets: [src/dotNet/StartUp.cs](https://github.com/Adrianotiger/desktopPet/blob/master/src/dotNet/StartUp.cs)
- `StartUp(ProcessIcon)` builds `Xml` and `Animations`, starts `timer1` (1000 ms).
- `Timer1_Tick` calls `AddSheep()` while `iSheeps` is below the auto-start count and below `MAX_SHEEPS`.
- `AddSheep()`: `new FormPet(animations, xml)`, `AddImage` for each sprite, stores it in `sheeps[iSheeps]`, `Show(...)`, `Play(true)`.
- Cap: `public const int MAX_SHEEPS = 16;`. At the cap it logs a "max PETs reached" warning.
- Storage: `public readonly FormPet[] sheeps` plus `int iSheeps`. `KillSheep(FormPet)` shifts the array. Each pet is its own WinForms window.
- `LoadNewXMLFromString` kills all pets and restarts creation with a new pet definition.

### Child animations
- Data: [Animations.cs](https://github.com/Adrianotiger/desktopPet/blob/master/src/dotNet/Animations.cs): struct `TChild { Position (TMovement), AnimationID, Next }`, store `Dictionary<int, List<TChild>> SheepChild`,
  `AddChild`, `SaveChild`, `HasAnimationChild(id)`, `GetAnimationChild(id)`. Spawns: `TSpawn { Start, Probability, Next }`, `GetRandomSpawn()`.
- Creation: [FormPet.cs](https://github.com/Adrianotiger/desktopPet/blob/master/src/dotNet/FormPet.cs) `SetNewAnimation(int id)`: if `HasAnimationChild(id)`, for each `TChild` it creates
  `new FormPet(Animations, Xml, <parent position>, !IsMovingLeft, DisplayIndex)`, copies frames, names it `child1`..., `Show`, `PlayChild(id, childInfo)`; children kept in a `childs` list. `Kill()` closes all children.
- Nesting cap: children spawn further children only while the name's number is below 5 (about 5 levels). No global child cap in that file; children are not counted in `MAX_SHEEPS` (UNVERIFIED).
- XML-side docs: wiki pages XML\Child and XML\Spawn exist, but I could not read their content (https://github.com/Adrianotiger/desktopPet/wiki).

### Can two pets interact? Yes, in FormPet.cs
- `NextStep()` calls `SetPetInteractionAnimations(rct)` when horizontal movement hits a window titled `"Sheep"` (found by `EnumerateWindows()`).
- `SetPetInteractionAnimations` finds the other pet by matching Left/Bottom against `Program.Mainthread.sheeps` and their `childs`, then picks one of 3 outcomes: shared border animation, mimic the other's animation (50%), or a random `PETSIDE` border animation.
- `FallDetect` and `CheckTopWindow` treat a "Sheep" window as a surface, so pets can land on each other.
- Reported inconsistency: `EnumerateWindows` checks "Sheep", `CheckTopWindow` checks "sheep" (UNVERIFIED, from the summary).
- The app is MIT and recent commits add collision/interaction (PR #167, see R14.1), so this code is still moving.

## Answer for Cuy
Multiple pets = several `FormPet` windows in `StartUp.sheeps[]` (max 16, `AddSheep()`); children are extra `FormPet`s created in `FormPet.SetNewAnimation` from `<childs>` (depth cap about 5).
Two pets can interact (`SetPetInteractionAnimations` when one hits a window titled "Sheep"), not only spawn children. Matching is by window title and position, so a second Cuy pet would need a unique window title.
