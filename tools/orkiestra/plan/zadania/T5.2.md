## Facts about the tool
- Install: `pip install -e .` (Python 3.11+). Requires `git`, `gh` (logged in: `gh auth login`), Antigravity CLI
  `agy` logged in once interactively. Check `agy -p "Reply with exactly: OK" --output-format json` prints JSON.
- Commands: `orkiestra init` (creates orkiestra.toml, waves.yaml, .gitignore entries, CI workflow if none),
  `orkiestra validate [--plan waves.yaml]`, `orkiestra run [--plan] [--wave W] [--task T] [--dry-run] [--no-wait]`,
  `orkiestra status`, `orkiestra mark <task> <pending|merged|skipped|needs_human>`, `orkiestra clean [--all]`.
  Global: `--repo PATH`, `--config PATH`, `-v`. Also runnable as `python -m orkiestra`.
- Exit codes of `run`: 0 all merged, 1 some task needs a human, 75 stopped because of Antigravity quota (`--no-wait`),
  2 configuration/plan error, 130 interrupted (state saved; just run again).
- Flow per task: worktree `orkiestra/<wave>/<task>` from `origin/main` → one fresh `agy -p` run (Flash) → orkiestra
  checks the agent only changed files from `files`, runs `test_command`, commits → after the whole wave: one by one
  rebase, push, PR, wait for GitHub CI, squash merge, delete worktree. Next wave starts only when the previous one is
  fully merged. Max 2 attempts per task (the 2nd gets the error/test output as feedback); then "WYMAGA CZŁOWIEKA".
- Quota: detected from agy errors (RESOURCE_EXHAUSTED/429/quota). Orkiestra stops starting new tasks, waits until the
  reset time from the message (or `quota_wait_minutes`), then continues. A quota hit does not count as an attempt.
- State: `.orkiestra/state.json`, logs per attempt in `.orkiestra/logs/<task>-a<N>.log`, summary
  `.orkiestra/summary.md`. Custom prompt template: put `task_prompt.md` into `.orkiestra/`.
- The agent writes `.orkiestra-result.json` (`{"status":"done"|"blocked","note":...}`); "blocked" = needs human at once.
- Config `orkiestra.toml` sections and keys: `[project] base_branch, remote, test_command, merge_mode (github|local)`;
  `[agent] cmd, model, timeout_minutes, skip_permissions, add_dir, output_format (json|text), use_pty, extra_args`;
  `[run] max_parallel, max_attempts, quota_wait_minutes, ci_timeout_minutes, worktree_dir, state_dir, stop_on_failure`.
  `use_pty = true` only for old agy that prints nothing in scripts; `add_dir = false` if `agy --help` has no `--add-dir`.
- Security: `skip_permissions = true` passes `--dangerously-skip-permissions`; acceptable because each agent works in an
  isolated worktree and orkiestra rejects changes outside `files`. Stricter option: the `vendor/agy-auto` hook.

## `docs/PISANIE_PLANU.md`
Explain the waves.yaml format (copy the example below) and the rules for good tasks:
1 task = 15–60 min of agent work; tasks in one wave never share files (validated); ≤ 3 tasks per wave; each prompt is
self-contained (the agent sees nothing else: name exact files, functions, signatures, expected behaviour, tests to
write, the command to run); put shared contracts (types, interfaces) into an earlier wave; give `test_command` per task
when possible; prefer small precise prompts over long essays.
Then include this planner prompt VERBATIM in a code block, under the heading "Prompt dla Opusa / modelu planującego":

```
Jesteś architektem. Rozpisz poniższy cel na plan dla narzędzia orkiestra w formacie waves.yaml (version: 1).
Zasady:
- Fale wykonują się po kolei; zadania w jednej fali równolegle, więc NIE mogą mieć wspólnych plików (pole files, glob).
- Maks. 3 zadania na falę. Pierwsza fala tworzy wspólne kontrakty (typy, interfejsy, szkielet), na których opierają się kolejne.
- Każde zadanie to 15–60 minut pracy dla szybkiego modelu (Gemini Flash), który NIE zna reszty planu.
- Prompt każdego zadania jest samowystarczalny i po angielsku: kontekst w 1–2 zdaniach, dokładne pliki do utworzenia/zmiany,
  sygnatury funkcji, oczekiwane zachowanie, testy do napisania, komenda weryfikacji. Bez ogólników.
- Dla każdego zadania podaj test_command uruchamiający tylko jego testy, jeśli to możliwe.
- Nie każ agentowi commitować, pushować ani czytać całego repozytorium.
Zwróć WYŁĄCZNIE poprawny YAML.

Cel projektu:
<opisz tutaj, co ma powstać, stack, istniejące pliki, konwencje>
```
