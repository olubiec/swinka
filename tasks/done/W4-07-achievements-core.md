Goal: About 20 one-time achievements with clover rewards exist in Core. Evaluation is pulled by the app (`Pet.CheckAchievements()`); nothing in `Pet.cs` changes.
Depends on: W1-06 (bond), W2-03 (diary), W3-08 (tricks) merged. Data-table pattern as `EconomyConfig` / `BondUnlocks` / `TricksConfig`: static `Current`, `Load(string)`, `LoadDefault()`, errors through `ItemCatalog.ErrorLogger`, injectable table on `Pet` so tests never touch statics.
Facts: Counters live in `State.Stats.Counters` (`Pet.Count(name)`). Counters that exist today: `feedings`, `pets`, `calls`, `purchases`, `cleanings`, `poops_collected`, `minigames_played`, `tricks_performed`, `trick_<id>`, `eaten_*`, `played_*`. Other facts come from state: `Stage`, `BirthdaysCelebrated`, `State.Bond.Level`, `State.Diary.Count`, `State.MinigamesDailyCount`, `Pet.IsUnlocked(id)`. Design rules: a short list weighted to easy and medium with a few hard ones; reward care and discovery; no trivial and no grind achievements.
Steps:
1. `achievements.json`: `{ "achievements": [ { "id", "title", "text", "category": "care|play|growth|social", "hidden": false, "rule": { "kind", "name", "atLeast" }, "reward": 50 } ] }`. Rule kinds: `counter` (name = a counter above), `stage` (atLeast = stage index), `birthdays`, `bond_level`, `diary_entries`, `minigames_today`. Include about 20, for example: first meal, 100 pettings, 10 minigame plays, 3 plays in one day, first birthday, reached Junior, Adult, Senior, Legend, bond level 5 and 10, all four tricks learned, 50 poops cleaned, 30 purchases, first diary entry, 10 diary entries. Use only rules the current code can measure; if an idea needs a counter that does not exist, skip it and list it in the PR. Rewards 50 to 200, numbers only in the file.
2. `AchievementCatalog` (data table with the pattern above; invalid or duplicate ids dropped and logged). `AchievementEvaluator.Check(...)` is pure: given the catalog and a snapshot of counters and state it returns the ids that are newly satisfied.
3. `GameState.Achievements.cs` (partial, like the other `GameState.*.cs`): earned ids with UTC dates, default empty, null-safe; old saves load.
4. `Pet.Achievements.cs`: `AchievementsTable` (null = `Current`), `IReadOnlyList<AchievementInfo> CheckAchievements()` that grants each newly earned one once (`AddClovers(reward)`, a diary line "Achievement: <title>", counter `achievements_earned`), raises the new event `AchievementEarned` (`EventHandler<AchievementEarnedEventArgs>` with id, title, reward), and returns the list. `GetAchievements()` returns every achievement with `earned`, `date`, `hidden`.
5. Tests: each rule fires once only, reward added once, save and load keeps earned ids, unknown rule names are ignored, the real `achievements.json` loads with at least 15 entries and unique ids, a default `new Pet(...)` does not change any existing number until `CheckAchievements()` is called.
