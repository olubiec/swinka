# W3-03: The pig writes one diary entry per evening (Core)
Goal: in the real app the pig adds at most one diary entry per local day, in the evening, only for days with activity, from the templates.
Depends on: W2-03 (`DiaryWriter`, `DiaryContext`, `DayStats`) merged. `Pet.AddDiaryEntry`, `GameState.Diary`, `Pet.GetFavoriteVegetable`, `Pet.IsSick`, `Pet.Count` exist. Flag pattern as in W2-04 (`Balance.HayRackActive`): the new behavior is off in `new Balance()` so existing tests keep their numbers, and switched on in `GameSession.Open`.
Change: new `src/Cuy.Core/GameState.DayLog.cs`, new `src/Cuy.Core/Pet.Diary.cs`, `src/Cuy.Core/Pet.cs` (one call in `Update`), `src/Cuy.Core/Balance.cs` (two properties), `src/Cuy.Core/GameSession.cs` (one line in `Open`), new `tests/Cuy.Core.Tests/DiaryDailyTests.cs`
Do not touch: everything not listed under Change; in particular `AGENTS.md`, `docs/PLAN.md`, `tasks/*`. Another task of this wave may later edit other places of `Pet.cs`: keep your diff to your own lines, no reformatting.
Steps:
1. `Balance.DiaryActive` (bool, default false; the app turns it on in `GameSession.Open`, next to `HayRackActive`) and `Balance.DiaryWriteHour` (int, default 20; local hour from which the day's entry is written).
2. `GameState.DayLog.cs` (`partial class GameState`, follow the other `GameState.*.cs`): `DayLogDate` (string, `yyyy-MM-dd`), `DayLogCounters` (`Dictionary<string,int>`, default empty, null-safe), `DiaryLastWrittenDate` (string), `DiaryLastTemplateId` (string). Old saves must load.
3. `Pet.Diary.cs`: `bool TryWriteDiary(DiaryWriter writer = null, Random rng = null)` (writer null means `DiaryWriter.Current`, rng null means a shared `Random`). Rules, in this order: do nothing when `!Balance.DiaryActive`; `today` = local date from `Clock.LocalNow()`; if `DayLogDate != today` then `DayLogDate = today`, `DayLogCounters` = a copy of `State.Stats.Counters`, return false (the day's counting starts now); if the local hour is below `DiaryWriteHour` or `DiaryLastWrittenDate == today` return false; set `DiaryLastWrittenDate = today` (so a day without activity is not retried every tick); `DayStats.FromCounters(today, DayLogCounters, State.Stats.Counters)`; no activity means no entry; otherwise build a `DiaryContext` (`Name`, `Stage`, `Mood` low below 35, high above 70, else ok, `Sick = IsSick`, `Birthday = false`, `Weather = "any"`, the four counts, `Clovers = State.Clovers`, `FavoriteVegetable = GetFavoriteVegetable()`, `PreviousTemplateId = DiaryLastTemplateId`), render, and when the result is not null call `AddDiaryEntry(text)`, store the template id and return true. After adding, keep at most 365 entries (drop the oldest).
4. `Pet.Update()`: after `CheckAll();` add `TryWriteDiary();` (nothing else changes in `Pet.cs`).
5. Tests (`ManualClock`, seeded `Random`, a small in-test `DiaryWriter.Load(...)` JSON or the real file through `RepoFile`; `new Balance { DiaryActive = true }` only inside these tests): no entry before 20:00; one entry at 20:00 when the day had activity; none when it had none; never two on the same day (call it 100 times); the next day works again; the same template id is not used twice in a row; 400 simulated days stay at 365 entries or fewer; with the default `new Balance()` nothing is ever written; `GameSession.Open(clock, tempDir)` gives a pet whose `Balance.DiaryActive` is true; old save JSON without the new fields loads; save/load keeps `DiaryLastWrittenDate`.
Verify: `dotnet test tests/Cuy.Core.Tests/Cuy.Core.Tests.csproj -c Release` passes.
Prohibited: changing or deleting existing test assertions, new dependencies, touching files outside "Change".
