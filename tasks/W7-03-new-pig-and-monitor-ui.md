Goal: The player can start over safely (the old save is kept) and choose the monitor from the Settings screen.
Depends on: W6-06 (`settings.monitors`, `settings.monitor`, message `settings_monitor`) and W3-07 (settings UI) merged; mock keys exist since W5-08.
Facts: `SaveSystem` has `SavePath`, `BackupPath`, `FileName = "save.json"`, `Save(state)` and a load method returning `LoadResult`. The app saves on quit, so deleting the file while running is not enough: the reset must survive that final save. Design: a marker file makes the NEXT load start fresh.
Steps:
1. `SaveSystem.RequestReset()` writes the marker `reset.pending` in the save directory. The load method checks the marker first: if present it moves `save.json` (and `save.bak`) to `save.reset-<yyyyMMdd-HHmmss>.bak` (never deletes anything), removes the marker, and returns a fresh game (the normal first-run path). Name the helper `ResetKeepingBackup` if one is needed. Log `[Reset] ...`.
2. `SettingsFeature`: handle `settings_reset_confirmed {}` by calling `RequestReset()`, posting a toast "Cuy closes now. Start it again to meet your new pig.", then `Application.Exit()` through the same path the tray Quit uses (find it in `ContextMenus.cs`/`Program.cs`; do not edit them).
3. Settings page: a "Start a new pig" button opens an in-page two-button dialog: "Your pig will start as a baby. Clovers and items are lost. Cuy will close; start it again." with "Yes, start again" and "Cancel". Only the confirm button sends `settings_reset_confirmed`. A "Show the pig on" dropdown lists `settings.monitors` ("<name> <width>x<height>", the primary marked) with `settings.monitor` selected and sends `settings_monitor { index }`; hide the dropdown when only one monitor exists.
4. Tests in `SaveResetTests.cs` (temp directory, no statics): marker present gives a fresh state and keeps the old bytes in a `save.reset-*.bak` file; no marker leaves the save untouched; a fresh save migrates and loads again.
