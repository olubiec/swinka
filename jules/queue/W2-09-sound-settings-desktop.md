# W2-09: Sound settings in the desktop app: volume, quiet hours, mute in full screen
Goal: volume, quiet hours and "mute when a full-screen app runs" are saved, applied at start and can be changed through Home messages.
Depends on: W1-10 (`CareInput.TryTime`) merged. Facts: `SoundManager` already has `Volume` (saved through `Program.MyData`), `QuietHours` (`QuietHoursConfig`: `Enabled`, `Start`, `End`; default 22:00-07:00), `MuteOnFullScreen` (default true) and `IsSoundSuppressed(out reason)`, but only the volume is saved. `LocalData` keeps settings in `app.config` through `AppSettings[...]` and `Properties.Settings`; a missing key returns null, so every new getter must tolerate that. Settings state and messages live in `Features/SettingsFeature.cs` (not in `HomeWindow.cs`). The `SoundManager.IsFullScreenOrBusy()` detection bug is NOT part of this task.
Change: `src/Cuy/dotNet/LocalData.cs`, `src/Cuy/dotNet/SoundManager.cs`, `src/Cuy/dotNet/Features/SettingsFeature.cs`
Do not touch: everything not listed under Change; in particular `AGENTS.md`, `docs/PLAN.md`, `tasks/*`, `HomeWindow.cs`, `SoundPolicy.cs`, `web/*`.
Steps:
1. `LocalData`: new tolerant accessors, written the way the existing ones are, with defaults when the key is missing or unparsable: `GetQuietHours(out bool enabled, out TimeSpan start, out TimeSpan end)` / `SetQuietHours(bool enabled, TimeSpan start, TimeSpan end)` (stored as three string settings, `HH:mm`), `GetMuteFullscreen()` / `SetMuteFullscreen(bool)`. Defaults: enabled, 22:00, 07:00, true. If a new key needs an entry in `app.config` or `Settings.settings` to be stored, add it there and say so in the PR (list the files); do not change existing keys.
2. `SoundManager`: at construction load quiet hours and `MuteOnFullScreen` from `LocalData` into `QuietHours` and `MuteOnFullScreen`; add `SetQuietHours(bool enabled, TimeSpan start, TimeSpan end)` (updates the live config and saves) and make setting `MuteOnFullScreen` save the value. Wrap every `LocalData` call in try/catch with `BrainController.Log("[WARN] ...")`, like the existing code.
3. `SettingsFeature.AddState` adds to the `settings` object: `volume` (0-100 integer, from `SoundManager.Volume`), `quietHours` (`{ "enabled": bool, "start": "22:00", "end": "07:00" }`), `muteFullscreen` (bool), `soundSuppressed` (bool, from `IsSoundSuppressed(out _)`). Keep the existing keys (`petSize`, `sounds`, `autostart`).
4. `SettingsFeature.HandleMessage`: `settings_volume { value }` (integer 0-100, otherwise ignored; sets `Volume = value / 100f`), `settings_quiet_hours { enabled, start, end }` (times through `Cuy.Core.Care.CareInput.TryTime`; invalid values are ignored and logged `[Settings] ignored ...`), `settings_mute_fullscreen { on }`. Return `true` for the three types, `false` for others; never throw.
Verify: `dotnet build src/Cuy/Cuy.csproj -c Release -p:EnableWindowsTargeting=true` and `dotnet test tests/Cuy.Core.Tests/Cuy.Core.Tests.csproj -c Release` pass.
Prohibited: changing or deleting existing test assertions, new dependencies, touching files outside "Change" (plus `app.config` / `Settings.settings` only if step 1 needs them).
PR: what was done, decisions and why, the keys added and where they are stored, how to check by hand; "Windows check for the human": change nothing in the UI yet (W3-07 adds the controls); start the app twice and check `cuy.log` shows no `[WARN]` from `LocalData` or `SoundManager`.
