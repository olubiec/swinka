# W2-01: Calendar: load care data in the app, validate input, log
Goal: the calendar really has its tasks in the running app, rejects bad input and reports what it does in the log.
Depends on: W1-09 (`CareData`) and W1-10 (`CareInput`) merged. Facts (checked on main, 2026-10-27): PR #32 added `CalendarFeature.cs` (state, five `calendar_*` messages, a 30 s `Tick`, 20 min debounce) and `CareReminderForm.cs` (Done / Later / x), but nothing calls `Pet.SetCareTasks` or `Pet.SetCareConfig`, so `pet.CareTasks` is empty in the app: no tasks on the page and no reminders. `HomeFeatureBase.Initialize(BrainController)` runs once at start (`Program.cs`, `HomeFeatures.InitializeAll`).
Change: `src/Cuy/dotNet/Features/CalendarFeature.cs`, `src/Cuy/dotNet/CareReminderForm.cs`
Do not touch: everything not listed under Change; in particular `AGENTS.md`, `docs/PLAN.md`, `tasks/*`, `src/Cuy.Core/*`, `HomeWindow.cs`. Keep the form's constructor `(CareTaskDefinition task, BrainController brain)` and the Tick logic as they are.
Steps:
1. Override `Initialize(BrainController brain)` in `CalendarFeature`: `var data = CareData.Current; brain.Pet.SetCareTasks(data.Tasks); brain.Pet.SetCareConfig(data.WeightAlert, data.SnoozeMinutes);` and log `[Calendar] loaded N care tasks`; when N is 0 log `[Calendar] ERROR no care tasks (care.json missing or empty)`.
2. `AddState`: `snoozeMinutes` comes from `CareData.Current.SnoozeMinutes` (remove the hard-coded list). Everything else in the state keeps its shape (`docs/contracts.md`, calendar).
3. Validate every message with `CareInput` (Core, W1-10): `calendar_settings` pig names through `CareInput.CleanPigNames` (the list replaces `PigNames` only when the message contains `pigs`), `time` through `TryTime` (store the normalized string), `weekday` through `TryWeekday`, `everyDays` through `TryEveryDays`; `calendar_weight` grams through `TryGrams`, date through `TryDate(raw, Clock.LocalNow().Date, out date)` (no date means today), pig name must be one of the configured pigs; `calendar_snooze` minutes through `TrySnoozeMinutes`. An invalid value is skipped (other valid fields of the same message are still applied), logged as `[Calendar] ignored <type>: <field> <reason>`, and never throws.
4. Unknown or missing task ids (`calendar_done`, `calendar_snooze`, `calendar_settings` entries) are ignored and logged the same way: no animation, no saving, no clover reward. Handlers return `true` once the message was recognised as a calendar message.
5. Wrap each handler body in try/catch that logs `[Calendar] handler error: <message>` and returns `true`.
6. `CareReminderForm`: log `[Calendar] card shown: <taskId>` when it opens and `[Calendar] card closed: <taskId> (done|later 60|later 15|auto-hide)` when it closes; the form already calls `HomeWindow.NotifyStateChanged()` after Done and Later: keep that. In `CalendarFeature.HandleMessage`, when `calendar_done` or `calendar_snooze` comes from Home and the card for that task is open, close it (already done for `calendar_done`: add `calendar_snooze`).
7. Leave the full-screen test as it is (`FormPet.ActivePet.TopMost` is a proxy; a later task replaces it with `FullscreenDetector`). Add a one-line comment saying so.
Verify: `dotnet build src/Cuy/Cuy.csproj -c Release -p:EnableWindowsTargeting=true` and `dotnet test tests/Cuy.Core.Tests/Cuy.Core.Tests.csproj -c Release` pass.
Prohibited: changing or deleting existing test assertions, new dependencies, touching files outside "Change".
PR: what was done, decisions and why, the list of message types with their validation rules, how to check by hand; "Windows check for the human": start the app, open Home > Calendar (nine tasks are listed with their times), set one task time 2 minutes ahead, wait: the pig wheeks, the card appears above it, Done gives clovers once and the card closes; `%LocalAppData%\Cuy\logs\cuy.log` shows `[Calendar] loaded 9 care tasks`.
