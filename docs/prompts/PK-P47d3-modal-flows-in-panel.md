## Pliki i elementy (zweryfikowane)
- CSS (`menu-panel.css`): `#gameDevice .modal-backdrop { top: var(--hud-h); padding: 0; background: var(--ui-linen-2); z-index: 50 }` so the HUD strip stays clickable, `#gameDevice .modal-card { max-width: none; max-height: none; width: 100%; height: 100% }`, `.modal-body` flexes to fill and scrolls inside (`overflow-y: auto; min-height: 0`). The Games screen and minigame canvases must fit 632x~350: `tools/qa/minigame-fit-check.js` is checked by q, not here.
- `app.js`: after the IIFE builds `elements`, register three providers: `CuyMenuPanel.register('shop', { open: () => CuyHome.openFeature('shop'), close: closeModal })`, `games` -> `openMinigamesModal`, `more` -> `openMoreModal`. The three HUD handlers become `Sound.click(); CuyMenuPanel.toggle('<id>')`. `closeModal()` (and the Esc path) must tell the panel: call `CuyMenuPanel.notifyClosed()` (new, in `menu-panel.js`: clears `current()` without calling the provider's `close`) so `current()` never stays `shop` after the modal is closed by its own x, a backdrop click or a feature.
- Opening any panel closes the other kind: `CuyMenuPanel.open('feed'|'pig')` first closes an open modal (`closeModal()` through a `beforeOpen` hook, set by app.js), and a provider-backed `open` first closes a mounted panel. A feature opened from elsewhere (`CuyHome.openFeature('shop')` by the pig, daily, tricks) closes a mounted panel too (call `CuyMenuPanel.close()` at the top of `openModal`).
