Goal: A pet can adopt a named pig or the starter pair, switch a pig to memorial mode, and announce new offers.
Depends on: W12 merged (OfferChecker, LegendRoll, offer state fields, ActiveModifiers).
Facts: Design: docs/NAMED_PIGS.md sections 2, 4.3, 4.4, 5. Costs: starter pair 0, james/glen/racuch `OfferCost` (100), memorial adoption always free and immediate. Welcome pack = items only (2 bell_pepper, 2 parsley) and not for the starter pair or memorial adoption. Counters via `Count(name, by)`: `pigs_arrived` (named pig adopted from a non-starter offer), `memorial_pigs` (once per pig switched to or adopted in memorial mode). Roster cap: `max_roster` from pigs.json is read by the feature; here use a `MaxRoster` property (default 7). Keep changes in `Pet.cs` to the wiring of `Brain.ModifiersProvider = () => ActiveModifiers;` (and nothing else). Diary: use the existing diary writer entry points (find how `Pet.Diary.cs` records events). Test rules: use `RepoFile(...)` for repo files, inject tables and `Random`/clock instead of assigning statics (`Current`), keep tests deterministic.
Steps:
1. Events: `OfferUnlockedEventArgs(string pigId)` and `PigAdoptedEventArgs(PigProfile pig, bool memorial)`, exposed as `OfferUnlocked` and `PigAdopted` events on `Pet`.
2. `AdoptResult` enum (Ok, UnknownPig, AlreadyAdopted, NotUnlocked, NotEnoughClovers, RosterFull) and `AdoptResult AdoptNamed(string pigId, bool memorial, Random rng, DateTime nowUtc)`: checks in this order (the roster limit counts only living pigs that are not in the `legend` stage and not memorial, so legends and memorial pigs never block a new adoption); creates the profile (Name, Breed = look breed, PaletteId = look palette id, Traits, NamedId, `BornAtUtc = PigLife.BornAtFor(now, startAge, pigDaysPerRealDay)`, `ArrivedAtUtc`, `LegendAtYears` from `LegendRoll`, `Memorial`), spends the cost, adds the welcome items, counters, diary line, raises `PigAdopted`. `AdoptResult AdoptGroup(string groupId, ...)` adopts every pig of the group that is not yet adopted, all free, stops with the first failure.
3. `bool SetMemorial(string pigId, bool on)` toggles the flag (counter only the first time per pig), returns false for an unknown pig. `IReadOnlyList<string> CheckOffers(DateTime nowUtc)`: when the offers clock is null start it at `nowUtc` (only if the pig count is > 0), use `OfferChecker.Due`, add the ids to `OffersSeen`, raise `OfferUnlocked` for each non-starter one, return the new ids. Everything is behind `Balance.ArrivalsActive` (off: `CheckOffers` returns empty, adoption methods still work for tests).
4. Tests (`PetAdoptionTests.cs`, inject the real catalog): starter pair adoption is free and gives kuki + ned with `LegendAtYears` inside their ranges; james before day 90 is `NotUnlocked`, at day 90 with 100 clovers it is `Ok`, spends 100, grants 2+2 items and `pigs_arrived == 1`; with 99 clovers `NotEnoughClovers`; a second adoption of the same pig is `AlreadyAdopted`; a full roster (7) gives `RosterFull`; memorial adoption of racuch before day 130 is `Ok`, free, `Legend`, `memorial_pigs == 1`, no welcome items; `SetMemorial` twice on one pig counts once; `CheckOffers` at day 0 announces nothing for the starter pair, at day 91 announces james exactly once, a second call returns empty; the events fire with the right arguments.
