## Pliki i elementy (zweryfikowane w repo 8.11.2026; nie szukaj ich drugi raz)
- Line numbers below are from 8.11.2026, BEFORE waves P39 and P45 (they edit `canvas-pig.js`, `scenes.js`, `places/feature.js`, `index.html`). Find every function by name with grep, never by line.
- `web/home/canvas-pig.js` `bindEvents()` (~675-730): `this.drag = {startX,startY,moved}` set on `pointerdown` over the pig (`isOverPig`); on `pointermove` the drag moves `pigX/pigY` clamped to `this.walk`; the "out of window" test is `e.clientX < rect.left - 12 || e.clientX > rect.right + 12 || e.clientY < rect.top - 12 || e.clientY > rect.bottom + 12` (pointer is captured, so events continue outside) and then `this.drag = null`, `suppressClick = true`, `bridge.send({type:'take_out'})` (~706). `endDrag` (pointerup/cancel) clamps the pig to `walk`. Existing walk-to-edge exits (`setExitsEnabled`, `onPigExit`, ~447-510) are a separate mechanism: leave them.
- New API (add to class + the `CanvasPig`/`PigCanvas` wrappers ~1596-1664 like `setScene`): `setEdgeNeighbours({left,right})` (booleans, default both false = old behaviour), `onEdgeHold` (callback property, called with `{side:'left'|'right'}`), `continueDrag(side)`, `onDrop` (callback property, called with `{x,y,scene}`; `scene` = `this.sceneId`). `debug()` (~572) gets `edge: {side|null, progress 0..1, armed}`.
- Edge zone is measured in CSS px of the canvas rect (`getBoundingClientRect()`), outer 12 px on the left/right: independent of the scene scale and of the later P47 640x400 / fit change. Const `EDGE_ZONE_PX = 12`, `EDGE_HOLD_MS = 600`.
- Out-of-window rule changes: top/bottom beyond 12 px always `take_out`. Left/right beyond the rect: if `setEdgeNeighbours` has that side true, it counts as being IN the edge zone (clamp the pig, no `take_out`); if false, old behaviour (`take_out`).
- `continueDrag(side)`: the host has already called `CuyPlaces.applyScene` which called `setScene` (pig stays on the pointer: `pigX` is clamped into the new `walk`; `setScene` resets targets), so `continueDrag` only keeps `this.drag` alive with `moved = true`, clears the hold progress and sets `armed = false`; it re-arms when the pointer leaves the zone. No scene argument.
- Arrow indicator: a library sprite `assets/ui/arrow_left.png` / `arrow_right.png` (`assets/ui/` has them plus `_pressed`), drawn on a canvas layer (`CuyRoom.addLayer`-style or at the end of the draw pass) at the edge, growing from 1x to 2x (integer steps only) as the hold progresses.
- Snapping on drop (PK-P39c): the free-cell snapping of the drop point uses the grid API from `docs/opt/log/PK-P39c.md`; `onDrop` receives the snapped coordinates.
