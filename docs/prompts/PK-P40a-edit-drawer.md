## Kontekst (fakty, nie szukaj drugi raz)
- Docelowa wizja: każde miejsce (pokoje domku, ogród, park, farma, targ) to scena w głównym oknie Home (pseudo-3D: widok z przodu z góry, podłoga z głębią, świnka chodzi w x i y, skaluje się z głębią, y-sort). Sceny: `assets/data/place_scenes.json` (`bg`, `walk` [x0,y0,x1,y1], `depthScale`, wyjścia), moduł `web/home/features/places/{feature,scenes}.js`, płótno `web/home/canvas-pig.js` (API w logach `docs/opt/log/PK-P33a.md`, `PK-P34a.md`, `PK-P36a.md`).
- Test właściciela 7.11 (P31-P37 wdrożone): świnka chodzi przez fontannę i inne elementy tła; skala świnki do sceny jest zła; belka miejsc przycina scenę (drzewa w parku, domek na farmie nie widać); tła scen nie mają światła/ambientu (`lib/lights.js`, `assets/data/lights.json`), który jest w oknach ogrodu i farmy.

- Wiadomości mostka (fakty): pokój/ogród `room_place {place,itemId,x,y}`, `room_move {place,uid,x,y}`, `room_remove {place,uid}`, `room_flip {place,uid}`, `place_upgrade {id}`, `place_unlock {id}`; targ `market_quote/market_buy/market_sell {itemId,count}`, `market_stall`; farma `farm_plant {plot,cropId}`, `farm_water {plot}`, `farm_harvest {plot}`, `farm_harvest_all`, `farm_buy {what}`, `orchard_plant/orchard_harvest {slot}`; świnka `places.pigMove {pigId,to}`, `places.pigPin {pigId,pinned}`, `take_out`. Pole `place` to id sceny (`salon`, `pig:<id>`, `dorm`, `garden`, `park`, `farm`, `market`).
- Testy: Playwright przez `tools/qa/lib/ux.js` (helpery `openHome`, `openMore`, `openFromMore`), mock przeglądarkowy per funkcja (`features/<f>/mock.js`, `CuyScenesMock.state('seven')` daje 7 scen). Testy uruchamia `tools/qa/ux-all.js` (pliki `ux-pN-*.js`).

## Pliki i elementy (zweryfikowane w repo 8.11.2026; nie szukaj ich drugi raz)
- Line numbers below are from 8.11.2026, BEFORE waves P39 and P45 (they edit `canvas-pig.js`, `scenes.js`, `places/feature.js`, `index.html`). Find every function by name with grep, never by line.
- Loader: `web/home/app.js` `loadFromList` (line ~897) loads ONLY `features/<id>/feature.js`, `feature.css` and (mock) `mock.js` for each id in `features/index.json`. So `places/edit-panel.js` can NOT be registered through `index.json` (do not touch it). `places` itself is hard-wired in `web/home/index.html`: `<link ... features/places/feature.css>` (line 30) and `<script src="features/places/scenes.js">` + `feature.js` (lines 303-304, before `app.js`). Add the new `<link>` for `edit-panel.css` next to line 30 and `<script src="features/places/edit-panel.js">` after `feature.js`.
- The places bar is static HTML in `web/home/index.html` (lines 71-76: `#placesBar`, `#placesPrevBtn`, `#placesBarTitle`, `#placesNextBtn`), not built by `feature.js`. `edit-panel.js` creates the `Edit` button itself and appends it to `#placesBar` (after `#placesNextBtn`), id `editBtn`, class from the same wood-button family as `.ui-arrow-right` (see `web/home/style.css` 1499-1600; add new CSS only in `edit-panel.css`).
- `web/home/features/places/edit-panel.js` and `.css`: NEW. Exposes `window.CuyEdit = { open(), close(), toggle(), isOpen(), render(state), itemsFor(state, sceneId) }`. Other packages call `open/close/isOpen` (P40d redirects the Decor 'edit' deep link to `CuyEdit.open()`).
- Item data comes from the STATE, not from the json file: `state.rooms.catalog[]` (built in `src/Cuy/dotNet/Features/RoomsFeature.cs` ~155) has `id,name,places[],w,h,layer,icon,owned,placed,repeatable`. Free count = `repeatable ? owned : owned - placed`. Same filter as `garden/feature.js` ~597 (`c.owned && c.places.indexOf(place) >= 0`) and `rooms/feature.js` (`saleKeyOf`: salon, dorm and `pig:*` use the house catalogue). `places[]` values in `assets/data/world_items.json` are `house|garden|park|farm` (house 38, garden 23, park 12, farm 4; market has none). Verify the exact value for a salon item in `features/rooms/mock.js` (catalog build) before filtering and write it in the log.
- Scene ids: `CuyPlaces.getCurrentPlace()` (`places/feature.js` ~457); `applyScene(sceneId, st)` (~275) runs on every scene change/state push: call `CuyEdit.render(st)` from a small wrapper, i.e. listen with `window.CuyHome.registerFeature`-independent `onState`: simplest is `CuyHome.api.onState` if it exists (grep `onState` in `app.js`), else poll `CuyPlaces.getCurrentPlace()` on `bridge` state events. Do NOT edit `places/feature.js` (not in Zmieniaj).
- Locked scene: `state.places.order[]` entry `{id,title,locked,unlockHint}`. Market has no placeable items: Edit is disabled there too (hint `Nothing to place here`).
- Icons in cards: `assets/icons/icons.json` + the existing icon resolver (grep `icon-` / `CuyIcons` in `lib/`); card = `item.icon` id.
- Toys (ball, tunnel, hay ball, toy house) were removed from the game: do not name them in code or tests. Tests must derive their expectations from `state.rooms.catalog` of the mock, never from hard-coded item ids of toys.
