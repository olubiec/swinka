## Item W17-01: RoomLayout operations: place, move, flip, remove
Files of this item: src/Cuy.Core/World/RoomLayoutOps.cs, tests/Cuy.Core.Tests/RoomLayoutOpsTests.cs
Goal: A pure model validates and applies item placement on a grid with layers.
Depends on: W16 merged (WorldState types, WorldItemCatalog, PlaceCatalog).
Facts: Rules (docs/WORLD.md section 2.1): grid `cols x rows`; the top `wall_rows` (2) rows are wall (only `wall` layer items go there, and wall items must lie fully inside them); `floor` items lie fully below the wall rows; `ground` items anywhere below the wall rows; items of one layer never overlap; `ground` and `floor` may overlap each other; indoor rooms have wall rows, outdoor places (`garden`, `park`, `farm`) have 0; an item must lie completely inside the grid; `Flip` mirrors only the picture (same footprint). Uids are generated by the caller (`Func<string>`).
Steps:
1. `public enum PlaceResult { Ok, OutOfBounds, WrongLayerArea, Overlap, UnknownItem, NotAllowedHere }` and a static class `RoomLayoutOps` with `PlaceResult CanPlace(RoomLayout room, int cols, int rows, int wallRows, WorldItemDefinition item, string placeId, int x, int y, string ignoreUid)`, `PlaceResult Place(...)` (adds a `PlacedItem`), `PlaceResult Move(room, ..., uid, x, y)`, `bool SetFlip(room, uid, bool flip)`, `bool Remove(room, uid)`, and `int CountPlaced(room, itemId)`.
2. Tests: every `PlaceResult` is reachable; two floor items overlapping are refused and adjacent ones are fine; a ground path under a floor item is allowed; a wall item in the floor area and a floor item in the wall rows are refused; moving an item onto itself is allowed (ignoreUid); outdoor places accept floor items in row 0; removing an unknown uid returns false; a 3x2 sofa at the last valid cell is Ok and one cell further is OutOfBounds.

## Item W17-02: Comfort: capped sum and mood-decay factor
Files of this item: src/Cuy.Core/World/Comfort.cs, tests/Cuy.Core.Tests/ComfortTests.cs
Goal: A pure function turns placed items into a comfort score and a mood decay factor.
Depends on: W16 merged.
Facts: Design: docs/WORLD.md section 2.3. Score = sum of `comfort` of every placed item in all rooms/places, capped at `ComfortCap` (100). Factor = `1 - MoodDecayReductionAtCap * score / cap` (1.0 at score 0, 0.85 at the cap). Comfort never changes clovers, age or health. Also a per-place score for the garden walk requirement (`min_comfort_garden`).
Steps:
1. `public static class Comfort`: `static int Score(WorldState world, WorldItemCatalog items, string placeIdOrNull)`, `static int Capped(int score, PlaceCatalog places)`, `static double MoodDecayFactor(int cappedScore, PlaceCatalog places)`.
2. Tests: empty world is 0 and factor 1.0; two sofas (comfort 6 each) give 12; a world above the cap is capped at 100 and the factor is exactly 0.85; unknown item ids contribute 0; per-place score counts only that place; the factor is monotonic non-increasing.

## Item W17-07: PlaceUnlock: requirements, costs and levels
Files of this item: src/Cuy.Core/World/PlaceUnlock.cs, tests/Cuy.Core.Tests/PlaceUnlockTests.cs
Goal: A pure helper decides whether a place, room or level can be unlocked and what it costs.
Depends on: W16 merged.
Facts: Data: `places.json` (garden 400, farm 600 requires garden, park 1200 requires garden; rooms bedroom 470, playroom 660; levels per place/room). House/salon/market are unlocked at the start. Level of a place: 0 = locked, 1 = first grid, 2, 3 higher grids (levels list index + 1). Costs of levels are in the list. The helper mutates `WorldState` and returns the cost; the caller spends clovers.
Steps:
1. `static class PlaceUnlock`: `UnlockResult CanUnlock(WorldState, PlaceCatalog, string placeId)` (Ok, Unknown, AlreadyUnlocked, MissingRequirement), `int UnlockCost(...)`, `bool Unlock(...)`, `UnlockResult CanUnlockRoom(...)`/`UnlockRoom`, `int NextLevelCost(WorldState, PlaceCatalog, string placeOrRoomId)` (-1 at max), `bool Upgrade(...)`, `(int cols, int rows) GridSize(WorldState, PlaceCatalog, string placeOrRoomId)`.
2. Tests: the farm needs the garden; unlocking twice is refused; levels advance 1 -> 2 -> 3 for the salon with costs 530 and 1200 (read from the file), never beyond; grid sizes match the file for every level; unknown ids are refused; a fresh `WorldState` reports house, salon and market unlocked.

## Item W17-08: LegacyDecorMigration: slot decorations become placed items
Files of this item: src/Cuy.Core/World/LegacyDecorMigration.cs, src/Cuy.Core/World/WorldState.cs, tests/Cuy.Core.Tests/LegacyDecorMigrationTests.cs
Goal: Old slot decorations (wallpaper, floor, rug, plant, picture, lamp) move into the Living room layout, once.
Depends on: W16 merged.
Facts: Today: `GameState.Decor.Equipped` maps slot -> item id (`wallpaper`, `floor`, `rug`, `plant`, `picture`, `lamp`); the items live in `assets/data/items_decor.json` and were bought into `Inventory`. Nothing may be deleted from the save. New: `WorldState.Rooms["salon"].Wallpaper/Floor` take the equipped wallpaper and floor ids; rug/plant/picture/lamp become `PlacedItem`s at fixed default cells (rug on the ground layer centre, plant right of the sofa area bottom row, picture and lamp on the wall rows), and every legacy item counts as owned (`OwnedItems`). The old slot items need entries in the placeable catalog: treat them as 1x1 (plant, lamp), 2x1 (picture, wall), 3x2 (rug, ground) items with comfort 2/1/2/1 and the price from `items_decor.json`; build these definitions in this class from `items_decor.json` data (a `LegacyItems(ItemCatalog)` method) rather than editing `world_items.json`. Idempotent: a flag `LegacyDecorMigrated` is added to `WorldState` (bool, default false).
Steps:
1. `static bool Migrate(GameState state, WorldItemCatalog items, ItemCatalog catalog)` returns true when it changed anything; second call returns false.
2. Tests: an empty `Decor` migrates to an empty salon and sets the flag; a decor with all six slots yields wallpaper and floor ids plus four placed items inside the 12x7 grid without overlaps; items are in `OwnedItems`; the old `Decor.Equipped` is unchanged; calling twice does not duplicate; unknown item ids are skipped.
