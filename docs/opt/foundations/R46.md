## 2. Placement pipeline today

1. Pipeline trace: room_place message validated by src/Cuy.Core/Input/Validation/RoomsMessages.cs:10-16 (place, itemId, x, y in [-1, 200], flip). Handled in src/Cuy/dotNet/Features/RoomsFeature.cs:367-380; ResolveGridCoordinates (RoomsFeature.cs:595-692) converts pixel coordinates to grid cells (rawX / 16.0 - w / 2.0, rawY / 16.0 - h). Pet.PlaceItem (src/Cuy.Core/Pet.Rooms.cs:129-196) verifies Balance.WorldDecorActive and world.OwnedItems[itemId] >= placed + 1, then calls RoomLayoutOps.Place (src/Cuy.Core/World/RoomLayoutOps.cs:166-200). RoomLayoutOps.CanPlace (RoomLayoutOps.cs:32-87) checks IsAllowedInPlace(item, place) and bounds 0 <= x <= cols - w, 0 <= y <= rows - h.
2. Key validity: garden and park are valid in assets/data/places.json:6-26 (levels 16x9 and 24x12). farm and market have levels: [] in places.json:16-30, so Pet.GetRoomGridSize (Pet.Rooms.cs:68-110) returns (0, 0), causing RoomLayoutOps.CanPlace to reject placements with OutOfBounds.
3. Coordinate units: PlacedItem.X/Y in src/Cuy.Core/World/WorldState.cs:140-141 are grid cells (1 cell = 16x16 px). world_items.json w/h are integer cells (bench_wood w=2, h=1). Static blockers in place_scenes.json are pixels [x0, y0, x1, y1].
4. Edit panel & drawer: web/home/features/places/edit-panel.js:704-717 (getItemKind) returns outdoor if item.places contains outdoor scenes. edit-panel.js:719-723 (getSceneKind) returns outdoor for garden, park, farm, market. edit-panel.js:751-753 filters items by getItemKind(item) === sceneKind. Because current items in world_items.json lack places, the outdoor drawer is empty today.
5. Stash: Unplaced inventory lives in WorldState.OwnedItems (WorldState.cs:20). Placed instances live in WorldState.Rooms[placeId].Items (WorldState.cs:129).
6. Scenes.js today: layoutFor (web/home/features/places/scenes.js:358-373) returns state.rooms.layouts[sceneId]. placedThings (scenes.js:522-578) returns [] because outdoor layouts do not yet exist in state.rooms.layouts.

### Seeding rule
- Add public HashSet<string> OutdoorSeeded { get; set; } = new HashSet<string>(StringComparer.OrdinalIgnoreCase); to src/Cuy.Core/World/WorldState.cs.
- OutdoorSeed.Seed(WorldState world, string placeId):
  - If world.OutdoorSeeded.Contains(placeId) or !Balance.OutdoorInstancesActive, return.
  - Create world.Rooms[placeId] if missing.
  - Add each default item with UID fx:<placeId>:<id> to world.Rooms[placeId].Items.
  - Add to world.OwnedItems[itemId] so stashed decorative items can be replaced from drawer.
  - Add placeId to world.OutdoorSeeded.
- If player stashes an object, it leaves world.Rooms[placeId].Items. Because placeId remains in OutdoorSeeded, the object is never re-seeded on subsequent loads.

### Classification: Decorative vs Fixture
- Decorative (movable: true, removable: true): benches, flower beds, trees, hedge, gazebo, lamp posts, fences, signs, notice board.
- Fixtures (movable: true, removable: false): market stalls, barn, burrow/tunnel, bridge, farm plots.
- Removing a fixture in RoomLayoutOps.Remove / RoomsFeature.cs returns error fixture_locked.

## 4. Rendering and walking

### Collision & Y-Sort Today
- this.blockerRects populated in web/home/canvas-pig.js:505-517 from this.blockers (from setScene(def).blockers) or lookupSceneBlockers(sceneId) (canvas-pig.js:459-490).
- isFree(x, y) (canvas-pig.js:588-600) tests bounds against this.walk and this.blockerRects.
- drawBackgroundBlockersOverPig(ctx) (canvas-pig.js:2482-2518) slices rectangular areas from sceneBgImg and paints over pig when pigFeetY < b.behindLine || ry1.
- Y-sorting for instances (canvas-pig.js:2167-2170) renders standing objects with y > pigFeetY in front of the pig.

### Deriving Blockers for bg_clean: true
- Scenes in assets/data/place_scenes.json get boolean bg_clean: false (default).
- In web/home/features/places/scenes.js:410-500 (def):
  - When template.bg_clean is true, blockers are derived dynamically from placedThings(state, sceneId).
  - For each instance, footprint rect [rx0, ry0, rx1, ry1] is computed from cell position and w/h.
  - Crucial technique: assign behindLine: -9999 to instance-derived blockers! In canvas-pig.js:2497, condition pigFeetY < base is never met, so drawBackgroundBlockersOverPig will never slice empty background over the pig. Standard Y-sorting handles depth naturally.

### File Conflicts with Parallel Packages
- PK-P44a edits canvas-pig.js; PK-P44b edits places/feature.js.
- PK-P43b edits canvas-pig.js and scenes.js; PK-P43c/d/e edit feature modules.
- By using behindLine: -9999 in scenes.js:def(), PK-P46b avoids editing canvas-pig.js and places/feature.js, eliminating merge collisions with PK-P44 and PK-P43.

## 6. Risks and decisions

### Decisions
1. Fixtures non-removable (movable:true, removable:false): Stalls, barn, plots, and burrow can be moved on walkable ground but not stashed. Attempting removal returns fixture_locked and shows a toast.
2. Deterministic UID scheme fx:<scene>:<id>: Defaults use stable deterministic IDs for idempotency across saves.
3. Per-scene bg_clean flag in place_scenes.json: Default false. Scenes switch to instance rendering independently as clean art is ready.
4. Grid dimensions for farm and market in places.json: Add levels: [{ level: 1, cols: 16, rows: 9 }] to farm and market in assets/data/places.json.
5. Handling non-standard sprite heights in WorldAssetsTests: Add tests/Cuy.Core.Tests/WorldAssetsTests.cs to PK-P46a Zmieniaj; allow heights <= cells * 16 and skip art: missing.
