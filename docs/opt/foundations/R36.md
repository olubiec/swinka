## 2. Algorytm Brain do odtworzenia w JS

Źródła: `src/Cuy.Core/AI/Brain.cs` (`DecideNextAction:321-426`, `CheckActionAvailability:492-599`, `CalculateScore:601-734`, `GetActionMultiplier:736-774`, `Interrupt/Resume:834-855`, `Update:863-916`) i `src/Cuy.Core/AI/Actions/*.cs` (puste klasy markerowe `EatAction, PlayAction, RestAction, WanderAction`).

1. **Dzień** (`323-328`): gdy `day !== currentDay`, zeruj `dailyCounts = {}`.
2. **Dostępność** (`492-599`): odrzuć jeśli: `simSec < cooldownsUntilSec[id]`; `dailyCounts[id] >= getDailyLimit(stage)` (`ActionDefinition.cs:175-198`, fallback `"adult"`); `consecutiveCount >= 2 && id === lastActionId`; niespełnione warunki (`mood_min/max`, `energy_min/max` [przy `userIdle && (id==='sleep'||id==='nap')` `maxEnergy=95.0` w `545-548`], `idle`, `idle_min_s`, `fullness_min/max`, `vitamin_c_min/max`, `health_min/max`, `hay_in_rack_min`, `item`, `companion`, `temperature_min/max`). Uwaga: `actions.json:319` ma `stage_min:"adult"` dla `rumblestrut`, czego `Brain.cs:531-594` nie sprawdza — JS sprawdza `stage_min`.
3. **Ocena** (`601-734`):
   - `satSum = sum((1 - need/100)^2 * effVal)`, `rand = 0.8 + rng()*0.4`, `score = satSum * rand + (base_weight||0)`, `*= stageMultiplier[stage]??1`.
   - Pora dnia (`630-679`): `isNight = (hour>=23||hour<7)`: `sleep/nap/rest_and_naps` `*=2.0`, `walking/sniffing_and_looking/play_and_rare` `*=0.5`; `(7<=hour<9 || 17<=hour<21)`: grupy aktywne `*=1.5`; `(11<=hour<15)`: `rest_and_naps` `*=1.6`; `PeriodMultipliers` bez podwójnego liczenia.
   - `userIdle` (`682-700`): jeśli `fullness>=15`: `sleep += 3.5`, `nap += 2.0`; `walking/zoomies/popcorn *= 0.5`.
   - Budżet dnia (`704-729`): `tot = max(1, sum(groupAcc))`, `deficit = targetPct - (groupAcc[g]/tot)*100`. Dla `scratch/scratching/chin_rub/chin_marking/popcorn/zoomies`: `score += 2.0`; inaczej `warmup = min(1, tot/1800)`, `needMul = (id==='eat_hay' && deficit>0) ? max(0, 1 - fullness/100) : 1`, `score += deficit * 0.8 * warmup * needMul`.
   - Modyfikatory (`736-774`): `activity` (`moves`/walk), `joy_weight` (`popcorn/dancing/zoomies/beaming`), `wheek_rate` (`wheeking`).
4. **Wybór i cykl** (`349-425`, `834-915`): max `score` (fallback `"rest"`, `0.5`). Zapisz `dailyCounts`, `consecutiveCount`, wylosuj `duration` z `duration_s`, ustaw `cooldownsUntilSec`. `Interrupt` zamraża timer; `Resume` wznawia jeśli `remainingMs > 500`, inaczej wybiera nową. JS nie mutuje `ctx.needs` bezpośrednio.

## 5. Kontrakt `pig-behavior.js` i schemat `home_behavior.json`

UMD (`web/home/lib/lights.js:1-3`): `window.PigBehavior` / `module.exports`. Zero DOM.

- `PigBehavior.create({ data, homeData, rng, now, stage, modifiers })`
- `tick(dtMs, ctx)`: `ctx` = `{ needs, stage, hour, sceneKind, hasSpot, otherPigNear, mood, sick, weather, dragging, modalOpen, hayInRack, items, musicPlaying, userIdle }` (`needs`: `fullness/satiety, vitamin_c/vitaminC, energy, mood, cleanliness, teeth, health`, domyślnie `50`; `hasSpot(kind)` -> boolean; `weather`: liczba `tempC` | `{tempC}` | `'cold'|'hot'`). Gdy `dragging || modalOpen`: pauza i zwraca `null`. Gdy trwa akcja (`remainingMs > 0`): odlicza `dtMs` i zwraca `null`. Po wyborze zwraca `{ id, anim, durationMs, loop, needsSpot, bubble, sound }` (`needsSpot`: `'sleep'|'sleep_together'|null`).
- `interrupt(reason)`, `resume(ctx)` (wznawia gdy `remainingMs > 500`, inaczej wybiera nową), `current()` (`{ id, anim, durationMs, remainingMs, loop, needsSpot, bubble, sound } | null`), `debug()` (`{ simMs, day, dailyCounts, cooldownsUntilMs, groupSeconds, lastActionId, consecutiveCount, interrupted, interruptedReason }`).
- Zasady: (1) ruch ma pierwszeństwo przed sprawdzaniem celu; (2) kliknięcie/karmienie/głaskanie przerywa przez `interrupt` i wraca przez `resume`; (3) brak akcji przy `dragging`/`modalOpen`; (4) brak miejsca (`!ctx.hasSpot(spot)`) pomija akcję; (5) `sick===true` blokuje `zoomies, popcorn, dancing`.
