### P7-01: Core room occupancy grid & placement validation without overlap, hanging item exception
- **Status: Partly** (Validation and overlap checks exist in Core, but under different file paths and discrete grid coordinates).
- **Proof & Evidence**:
  - Planned path `src/Cuy.Core/Decor/RoomOccupancy.cs` DOES NOT EXIST (`src/Cuy.Core/Decor/` does not exist).
  - Real implementation lives in `src/Cuy.Core/World/RoomLayoutOps.cs:32-131` via `CanPlace(RoomLayout room, int cols, int rows, int wallRows, WorldItemDefinition item, string placeId, int x, int y, string ignoreUid, WorldItemCatalog catalog)`.
  - Result enum: `PlaceResult` (`RoomLayoutOps.cs:7-14`): `Ok`, `OutOfBounds`, `WrongLayerArea`, `Overlap`, `UnknownItem`, `NotAllowedHere`.
  - Boundary check: `x < 0 || y < 0 || x + w > cols || y + h > rows` (`RoomLayoutOps.cs:59-62`).
  - Layer rules: `assets/data/world_items.json:4-8` defines layers `["ground", "floor", "wall"]`. `RoomLayoutOps.cs:64-88` enforces that items with `layer == "wall"` (paintings, clocks, windows) require `0 <= y && y + h <= wallRows`, whereas `floor` items require `y >= wallRows`.
  - Overlap check: `RoomLayoutOps.cs:118-126` evaluates overlap `!(x + w <= placed.X || placed.X + otherW <= x || y + h <= placed.Y || placed.Y + otherH <= y)` only when `sameLayer` is true. Wall-mounted items never collide with floor items.
  - Message handling: `src/Cuy/dotNet/Features/RoomsFeature.cs:367-404, 629` processes `room_place` and `room_move` through `RoomLayoutOps.CanPlace`.
  - **Gap**: `RoomLayoutOps.cs` operates strictly on discrete room grid cells (16x8 or 12x7). Outdoor scenes use continuous coordinates (0..256, 0..144) snapped to 4 px. Core does not validate static scene blockers (`place_scenes.json:20-140`); static scenery collision is currently enforced solely in front-end JS.
