## 2. Hotspots bind to objects

Legacy scenes used baked backgrounds with static rects in `assets/data/place_scenes.json:37-46, 65-80, 99-103, 122-129`.
With Wave P46, outdoor fixtures (stalls, plots, barn, fountain, benches) become saved instances in `WorldState.Rooms[scene].Items` (`src/Cuy.Core/World/WorldState.cs:26, 129`) with deterministic uids `fx:<scene>:<id>` seeded by `OutdoorSeed.Seed` (`PK-P46a`). In Edit mode (`PK-P46c`), players drag and reposition these instances across the walk area.

### Dynamic Resolution via `CuyScenes.hotspotsFor(sceneId, state)`
1. **Dynamic Derivation**:
   - In `web/home/features/places/scenes.js`, implement `hotspotsFor(sceneId, state)` (export on `CuyScenes` at line 580):
     - Retrieve placed instances via `placedThings(state, sceneId)` (`scenes.js:522`).
     - For each interactive item (kind `stall`, `plot`, `lamp`):
       - Anchor `(item.x, item.y)` and size `(sw, sh)` come from `placedThings` (`scenes.js:542-559`).
       - Bounding box in scene pixels: `rect = [item.x - item.anchorX, item.y - item.anchorY, item.x - item.anchorX + sw, item.y - item.anchorY + sh]`.
       - Emit hotspot `{ id: item.id, kind: itemKind, rect: rect, label: itemLabel, uid: item.id }`.
2. **Static Fallback**:
   - For scenes without clean backgrounds (`bg_clean: false`), or immutable landscape elements (pond, flowerbed, gazebo), static hotspots in `place_scenes.json` are appended.
   - Dynamic instance hotspots take precedence on id collision.
3. **Integration with CanvasPig & Edit Mode**:
   - `web/home/features/places/feature.js` calls `CanvasPig.setHotspots(CuyScenes.hotspotsFor(sceneId, state))` in `applyScene` (`places/feature.js:818, 830`).
   - In Edit mode (`window.CuyEditMode` or `.in-edit-mode`), `CanvasPig` suppresses hotspot hover/click so fixture dragging (`PK-P46c`) is uninterrupted.
   - On `room_move`, `applyScene` re-evaluates `CuyScenes.hotspotsFor` and pushes updated rects to `CanvasPig.setHotspots(...)`.
4. **Test Adjustments (`tools/qa/ux-p43-hotspot-data.js`)**:
   - Tests verify static fallback schemas in `place_scenes.json` and dynamic derivation via `CuyScenes.hotspotsFor` against mock instances.

## 3. Farm and market mapping

### Farm Plot Mapping
- **State Structure**:
  In `src/Cuy.Core/World/WorldState.cs:148-169`, `FarmState.Plots` holds `PlotState { CropId, PlantedUtc, Watered }`. `FarmState.PlotsOwned` defines active count. In JavaScript, `web/home/features/farm/feature.js:135` reads `const plots = f.plots || [];`.
- **Instance Binding**:
  In P46a, farm plots are seeded as instances `fx:farm:plot:0` .. `fx:farm:plot:N-1`.
  `CanvasPig.onHotspot` receives hotspot `plot:i` (or `fx:farm:plot:i`), and `farm/feature.js` extracts index `i`:
  - Empty plot (`state === 'empty'`): opens crop menu panel anchored at plot rect; sends `farm_plant { plot: i, cropId }`.
  - Growing unwatered (`!p.watered`): sends `farm_water { plot: i }`.
  - Ripe (`state === 'ripe'`): sends `farm_harvest { plot: i }`.
  - Growing watered: displays countdown tooltip.
- **Edit Mode Movement**:
  Moving a plot (`room_move { place: 'farm', uid: 'fx:farm:plot:i', x, y }`):
  - Updates `(X, Y)` in `WorldState.Rooms['farm'].Items`. Crop state in `FarmState.Plots[i]` is untouched.
  - Sprite, blocker rect (`CuyScenes.def().blockers`), and dynamic hotspot rect update together.
  - Removal/stashing returns `fixture_locked` error (`removable: false`).

### Market Stall Mapping
- **State Structure**:
  In `src/Cuy.Core/World/WorldState.cs:185-210`, `MarketState` tracks daily demand, sales, and `StallLevel`. In `web/home/features/market/feature.js:7-12`, inventory is grouped by category tabs: `seeds` (`category: 'seed'`), `home` (`category: 'decor'`), `pantry` (`category: 'pantry'`), and `sell`.
- **Instance Binding**:
  In P46, market stalls are seeded instances:
  - `fx:market:stall_seeds` (Center stall) -> opens Seeds & Tools panel (`buyRows(st, 'seed')`).
  - `fx:market:stall_pantry` (Left stall) -> opens Pantry food panel (`buyRows(st, 'pantry')`).
  - `fx:market:stall_decor` (Right stall) -> opens Home & Garden panel (`buyRows(st, 'decor')`).
  - `fx:market:stall_own` (Player cart) -> opens Sell tab (`sellRows(st)`) and level upgrade (`market_stall`).
- **Edit Mode Movement**:
  Moving a stall updates `(X, Y)` in `WorldState.Rooms['market'].Items`; market pricing and demand are untouched. Dynamic hotspot follows the instance. Removal returns `fixture_locked`.

## 5. Decisions and Prompt fixes

### Top 5 Decisions

- **Decision 1 (Order)**: Strictly **P44 -> P46 -> P43**. Gate D1 is obsolete (P39/P40 merged). P43 runs after P46 outdoor instances.
- **Decision 2 (Dynamic Hotspots)**: Hotspots for movable objects are generated dynamically in `scenes.js` via `CuyScenes.hotspotsFor` from `placedThings`. Static entries in `place_scenes.json` serve only as fallbacks.
- **Decision 3 (Farm & Market Mapping)**: Farm plots map 1:1 by instance index `fx:farm:plot:<i>` to `FarmState.Plots[i]`; plot status markers are drawn via `CanvasPig.addLayer` (D11). Market stalls map by instance category to `seeds`, `home`, `pantry`, and `sell` (D13). Moving fixtures in Edit mode preserves farm and market state; fixtures are locked against deletion (`fixture_locked`).
- **Decision 4 (Prune Obsolete Interactions)**: Toys (O2, D3), food drawer (O4, D5), and gramophone (O3, D6) are DROPPED. P43e handles only lamp toggles via `places/feature.js:765` (`toggleLamp`); remove `garden/feature.js` from `Zmieniaj:` (D4).
- **Decision 5 (Retire Windows Cleanly)**: In `web/home/app.js:927`, hide Farm and Market by checking `feat.id === 'farm' || feat.id === 'market'` (D7). Do NOT remove them from `features/index.json`.
