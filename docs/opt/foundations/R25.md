# R25: Fizyka stawiania lamp (uwaga 25)

## 1. Reguły stawiania dziś (Core i klient, plik:linia)

### Core (`src/Cuy.Core/World/RoomLayoutOps.cs`)
- `RoomLayoutOps.CanPlace` (`RoomLayoutOps.cs:32-131`) liczy `w`, `h` z `item.W` / `item.H` (`:56-57`).
- Granice: `x < 0 || y < 0 || x + w > cols || y + h > rows` -> `PlaceResult.OutOfBounds` (`:59-62`).
- Warstwy (`:64-88`):
  - `wallRows > 0` i `layer == "wall"`: wymaga `y >= 0 && y + h <= wallRows` -> `PlaceResult.WrongLayerArea` (`:67-73`).
  - `wallRows > 0` i `layer != "wall"` (`floor`, `ground`): wymaga `y >= wallRows` -> `PlaceResult.WrongLayerArea` (`:74-80`).
  - `wallRows <= 0` i `layer == "wall"`: `PlaceResult.WrongLayerArea` (`:84-87`).
- Kolizje `Overlap` (`:90-128`): prostokąt `[x, x+w) x [y, y+h)` tylko w tej samej warstwie (`sameLayer`, `:118-126`).
- `RoomLayoutOps.Place` (`:133-167`) i `RoomLayoutOps.Move` (`:169-233`) delegują do `CanPlace`.

### Bridge C# (`src/Cuy/dotNet/Features/RoomsFeature.cs`)
- `room_place` (`:367-401`) i `room_move` (`:402-435`) wołają `ResolveGridCoordinates` (`:595-685`), które bierze `h = def.H > 0 ? def.H : 1` (`:609`):
  - Auto-place (`rawX < 0 || rawY < 0`): `cy + h <= endY` (`:622-625`).
  - Piksele (`rawX >= cols || rawY >= rows`): `targetY = (int)Math.Round(rawY / 16.0 - h)` i clamp `Math.Min(rows - h, targetY)` (`:641-645`, `:662`).
  - **Błąd:** dla `lamp_mushroom`/`lamp_floor` (`h=2`, `floor`) `y` oznacza górę sprite'a, nie stopę; postawienie przy ścianie (`y_foot=2`) daje `y=1 < wallRows(2)` -> `WrongLayerArea` (toast `"Too close to the wall"`, `:395`). Dla `lamp_arc` (`h=3`, `wall`) `y + 3 <= 2` jest zawsze fałszywe.

## 3. Model danych: stopa vs wysokość sprite'a, pola i domyślne

Rozdzielamy **stopę blokującą** (podstawa na siatce `cols x rows` dla granic, `wallRows`, `Overlap` i pathfindingu) od **wysokości sprite'a** (obrazek może zachodzić wyżej na ścianę lub zwisać ze ściany).

### Nowe pola w `assets/data/world_items.json` i `WorldItemDefinition` (`src/Cuy.Core/World/WorldItemCatalog.cs`)
- `foot_w` -> `public int FootW { get; set; }` (domyślnie `0`, `EffectiveFootW => FootW > 0 ? FootW : (W > 0 ? W : 1)`)
- `foot_h` -> `public int FootH { get; set; }` (domyślnie `0`, `EffectiveFootH => FootH > 0 ? FootH : (H > 0 ? H : 1)`)
- `sprite_h` -> `public int SpriteH { get; set; }` (domyślnie `0`, `EffectiveSpriteH => SpriteH > 0 ? SpriteH : (H > 0 ? H : 1)`)

**Domyślne:** brak pól = dotychczasowe `w` i `h` (stare przedmioty i testy bez zmian).

### Zmiany w `assets/data/world_items.json` i `assets/world/atlas.json`
- `lamp_mushroom`, `lamp_floor` (`floor`, `1x2`): `"foot_h": 1, "sprite_h": 2`.
- `lamp_arc` (`wall`, `2x3`): `"foot_h": 1, "sprite_h": 3`; w `atlas.json` `"anchor": [16, 16]` (zaczep u góry `foot_h=1`, sprite 32x48 zwisa w dół).
- `lamp_salt`, `lamp_post`, `lamp_oil` (`1x1`), `fairy_lights` (`3x1`): bez zmian (`foot_h = h = 1`).

### Reguły z `foot_w` / `foot_h`
- `PlacedItem.Y` oznacza wiersz **stopy** (`foot_h`):
  - `layer != "wall"`: `y >= wallRows && y + footH <= rows` (`lamp_mushroom`/`lamp_floor`: `y=2..6`, w `y=2` podstawa przy ścianie, góra sprite'a zachodzi na ścianę).
  - `layer == "wall"` (`wallRows > 0`): `y >= 0 && y + footH <= wallRows` (`lamp_arc`: `y=0..1` na ścianie; `y >= 2` -> `WrongLayerArea`).
- `Overlap`: prostokąt `[x, x + footW) x [y, y + footH)` w obrębie `sameLayer`.
- `ResolveGridCoordinates` (`RoomsFeature.cs`) i `cellToPx` (`scenes.js`) używają `footW` / `footH`.

## 4. Skutki: pathfinding, y-sort, stare zapisy, kolizje z istniejącymi testami

- **Pathfinding (`canvas-pig.js:531-553`, `596-618`):** `rebuildGrid()` tworzy `standingFootprints` jako `width x bottom 4 px`. Dla lamp podłogowych podstawa działa poprawnie. **Poprawka:** `rebuildGrid()` (`:535`) musi pomijać `t.layer === 'wall'` (`if (!t || t.flat || t.layer === 'wall') continue;`), bo inaczej `lamp_arc` (`32x48`, `anchorY=16`) na `cy=1` sięgałby do `y=64` i blokował chodzenie (`walk[1]=40`).
- **Y-sort (`canvas-pig.js:2319-2365`):** `allStanding` sortuje po `t.y` (dół stopy). `lamp_mushroom` w `cy=2` ma `t.y=48` (świnka za lampą `pigY < 48` rysowana przed nią). `lamp_arc` (`anchorY=16`) ma `t.y=16..32 < walk[1]=40`, więc zawsze za świnką.
- **Stare zapisy:** `lamp_mushroom`/`lamp_floor` mogły stać tylko na `y=2..5`; przy `foot_h=1` wszystkie `y=2..5` spełniają `y >= 2 && y+1 <= 7`, więc stare układy pozostają w 100% ważne.
- **Kolizje z `tests/Cuy.Core.Tests/RoomLayoutOpsTests.cs` (`:23-185`):** wszystkie 9 testów używają definicji bez `FootH`/`SpriteH` (`EffectiveFootH == H`). **Brak kolizji** z żadną istniejącą asercją.
