# R44: Hay Hop minigame

## 1. Jak dodać minigrę (plik:linia)
1. **Logika + gra w `web/home/minigames/`**: gra wywołuje `root.Minigry.register({ id, name, icon, desc, start(config) })` (`web/home/minigames/minigames-api.js:218-224`; alias `root.MiniGames = manager` w `minigames-api.js:1148-1150`; wzorzec `web/home/minigames/hay-maze.js:331-335`).
2. **Rejestracja w `web/home/minigames/games.json`**: tablica ścieżek względem `web/home/minigames/` (`games.json:1`: `["veggie-rain.js", "nyan-cuy.js", "veggie-memory.js", "hay-maze-logic.js", "hay-maze.js"]`). `minigames-api.js:1162-1183` ładuje skrypty kolejno przez `<script>`, a `src/Cuy/dotNet/SelfTest.cs:657-671` sprawdza istnienie każdego pliku na dysku.
3. **Start i HUD**: `MinigryManager.start(gameId, customConfig)` (`minigames-api.js:804-947`) przekazuje do `gameDef.start(gameConfig)` obiekt `gameConfig` (`container`, `width: 360`, `height: 290`, `stageKey`, `pigLook`, `onTimeLeft`, `updateScore(newScore)`, `endGame(resultScore)` — `minigames-api.js:902-924`).
4. **Wysłanie wyniku**: `config.endGame(score)` wywołuje `MinigryManager.endGame`, który wysyła `root.bridge.send({ type: 'minigame_result', gameId, score })` (`minigames-api.js:1024-1026`). W trybie mock `web/home/bridge.js:800-807` udostępnia też `submitMinigameResult(gameId, score)`.
5. **Obsługa w C# / Core**:
   - `src/Cuy/dotNet/HomeWindow.cs:741-745` kieruje `"minigame_result"` do `HandleMinigameResult(gameId, score)` (`HomeWindow.cs:1019-1035`).
   - `Pet.RecordMinigameResult(gameId, score, out cloversAwarded, out isNewRecord)` (`src/Cuy.Core/Pet.cs:385-454`) zapisuje `State.HighScores[gameId]`, resetuje dzienny licznik przy zmianie daty (`State.MinigamesDailyDate`), wylicza koniczynki z `EconomyConfig.Current.Minigame` (`assets/data/economy.json:4`, `src/Cuy.Core/Economy/EconomyConfig.cs:79-89`), pilnuje limitów `RewardedGamesPerDay` (10) i `MaxCloversPerDay` (150), dodaje nastrój (`15.0` / `3.0` / `0.0` dla `score <= 0`) i ustawia `LastMinigameResult` (`src/Cuy.Core/Pet.Minigames.cs:3-16`).
6. **Walidacja komunikatów**: `MessageValidator` (`src/Cuy.Core/Input/MessageValidator.cs:56-85`) zbiera klasy `IMessageRuleSet` (`src/Cuy.Core/Input/IMessageRuleSet.cs:8-11`) przez refleksję z `src/Cuy.Core/Input/Validation/<Feature>Messages.cs`. Dotąd nie było pliku dla minigier — Hay Hop dodaje `HayHopMessages.cs` i `docs/contracts/hayhop.md`.

## 2. Reguły i fizyka Hay Hop z liczbami
- **Plansza logiczna**: `width = 360`, `height = 290` (`minigames-api.js:904-905`), pozycje w pełnych pikselach, `pixelArt: true`, `roundPixels: true`.
- **Świnka**: hitbox `w = 24, h = 18`, start na `x = 180, y = 240` nad szeroką kępą startową (`x = 180, y = 264, w = 80, h = 12`). Jedno życie.
- **Krok czasowy**: `dtSec = clamp(dtMs, 0, 50) / 1000` (ujemne `dtMs` traktowane jako `0`, `step(dtMs, input)` nie cofa czasu).
- **Fizyka pionowa**:
  - Grawitacja: `gravity = 760` px/s^2 (`vy += gravity * dtSec`).
  - Odbicie od kępy przy spadaniu (`vy > 0` i poprzedni dół `<=` góra kępy `+ 4`): zwykła kępa `vy = -340` px/s; sprężynująca (`spring`) `vy = -510` px/s (`1.5x`).
  - Maksymalna wysokość skoku: `340^2 / (2 * 760) = 76.05` px.
- **Sterowanie poziome**:
  - `moveSpeed = 210` px/s. Wejście `input.dir` z `[-1, 1]` (klawisze `ArrowLeft`/`ArrowRight`, `A`/`D`) lub wskaźnik myszy `dir = clamp((pointerX - pig.x) / 24, -1, 1)`.
  - Pozycja `pig.x` ograniczona do `[12, width - 12]` (brak wyjścia poza ekran przy długim trzymaniu lewo/prawo).
- **Kamera i wynik**:
  - Kamera przesuwa się tylko w górę: gdy `pig.y < cameraY + 120`, `cameraY = pig.y - 120`.
  - `maxHeightPx = Math.max(maxHeightPx, startY - pig.y)` (gdzie `startY = 240`).
  - `score = Math.floor(maxHeightPx / 10)` (1 pkt za każde 10 px wzniesienia; monotonicznie niemalejący, na starcie `0`).
  - Koniec gry: gdy `pig.y - cameraY > height + 24`, ustaw `gameOver = true` i wywołaj `endGame(score)` dokładnie raz.
- **Kępy siana i trudność**:
  - Typy kęp: `normal` (stała), `moving` (ruch poziomy `vx` `45..95` px/s, odbicie od `[w/2, width - w/2]`), `crumble` (rozpada się po jednym odbiciu), `spring` (wybicie `1.5x`).
  - Odstęp pionowy między kolejnymi kępami rośnie z wynikiem: `minGap = min(56, 34 + floor(score / 25))`, `maxGap = min(68, 52 + floor(score / 20))` — zawsze `< 76` px, więc każda kępa jest osiągalna.
  - Szerokość kępy maleje: `w = max(36, 56 - floor(score / 30) * 2)`, wysokość `h = 12`.
  - Wagi typów: `0..49` pkt: 90% `normal`, 10% `spring`; `50..149` pkt: 65% `normal`, 20% `moving`, 15% `spring`; `150+` pkt: 45% `normal`, 25% `moving`, 20% `crumble` (nigdy dwie `crumble` z rzędu), 10% `spring`.
- **Grafika z biblioteki (`assets/`) i paleta (`assets/data/style_palette.json`)**:
  1. Świnka: `MinigryPig.preload(scene, config.stageKey || 'adult')` (`minigames-api.js:23`) -> `assets/sprites/<stage>/spritesheet.png` (animacje `pig_popcorn` przy skoku, `pig_idle` w spoczynku, `minigames-api.js:128-155`).
  2. Kępa siana: `assets/world/garden/grass_tuft_1.png` i `grass_tuft_2.png` (`16x12`, `assets/world/atlas.json:1884-1914`) lub kafel `hay` (`12`) z `assets/icons/icons_16.png` (`assets/icons/icons.json:14`).
  3. Ikona koniczynki/HUD: `assets/icons/icons_16.png` klatka `13` (`"clover": 13`, `assets/icons/icons.json:15`), ładowana jak w `hay-maze.js:32`.
  4. Brakujące elementy (tło nieba, belki platform `normal`/`moving`/`crumble`, nakładka `spring`): prostokąty z palety `assets/data/style_palette.json` (`roles.sky.day`: `#8da9a8`, `#b9c9c4`, `#efdcb8`; `ramps.hay`: `#a97a2f`, `#d1a548`, `#e9c871`; `ramps.wood`: `#47281c`, `#6f4328`; `ramps.moss`: `#475f3f`, `#97a569`; kontur `#3a1d17`). Zakaz `#000000`, `#ffffff`, gradientów i blur.

## 3. Nagroda i ochrona przed oszustwem
- **Dane w `assets/data/hayhop.json`**:
  ```json
  {
    "game_id": "hay_hop",
    "points_per_clover": 10,
    "max_clovers_per_game": 40,
    "max_score": 5000,
    "min_duration_ms": 1000,
    "max_duration_ms": 3600000,
    "max_points_per_second": 25,
    "mood_rewarded": 15.0,
    "mood_unrewarded": 3.0
  }
  ```
- **Klasa Core (`src/Cuy.Core/Minigames/HayHopReward.cs`)**:
  - `HayHopConfig` (wzorzec `EconomyConfig`: `Current`, `Load(string path)`, `LoadDefault()`).
  - `HayHopRewardResult` (`int Clovers`, `double Mood`, `bool Rewarded`, `bool RejectedAsImpossible`).
  - `HayHopReward.Compute(int score, int durationMs, int dailyGamesCount, int dailyCloversToday, HayHopConfig config, EconomyConfig.MinigameConfig economy, double scoreMultiplier = 1.0)`:
    1. Jeśli `score <= 0 || durationMs < config.MinDurationMs || durationMs > config.MaxDurationMs || score > config.MaxScore`: zwraca `Clovers = 0, Mood = 0, Rewarded = false, RejectedAsImpossible = (score > 0)`.
    2. Limit tempa: `int maxPlausible = (int)Math.Ceiling((durationMs / 1000.0) * config.MaxPointsPerSecond);`. Jeśli `score > maxPlausible`: zwraca `Clovers = 0, Mood = 0, Rewarded = false, RejectedAsImpossible = true` (fałszywy/niemożliwy wynik).
    3. Limit dzienny: jeśli `dailyGamesCount >= economy.RewardedGamesPerDay || dailyCloversToday >= economy.MaxCloversPerDay`: zwraca `Clovers = 0, Mood = config.MoodUnrewarded, Rewarded = false`.
    4. Nagroda: `int eff = (int)Math.Round(score * scoreMultiplier, MidpointRounding.AwayFromZero);` `int raw = Math.Min(config.MaxCloversPerGame, Math.Max(0, eff / config.PointsPerClover));` `int remaining = Math.Max(0, economy.MaxCloversPerDay - dailyCloversToday);` `int clovers = Math.Min(raw, remaining);` -> `Rewarded = true, Mood = config.MoodRewarded`.
- **Kontrakt i walidacja (`docs/contracts/hayhop.md`, `src/Cuy.Core/Input/Validation/HayHopMessages.cs`)**:
  - `HayHopMessages : IMessageRuleSet` definiuje regułę `"minigame.hay_hop.result"` z polami: `FieldRule.Int("score", 0, 5000)`, `FieldRule.Int("durationMs", 0, 3600000)`, `FieldRule.Str("seed", 32, required: false)`.
  - Statyczny helper `HayHopMessages.ValidateResultPayload(JObject message)` (wzorzec `RunMessages.ValidatePigPayload`, `src/Cuy.Core/Input/Validation/RunMessages.cs:24-37`) zwraca `null` dla poprawnego JSON lub kod błędu (`"null_message"`, `"missing_score"`, `"invalid_score"`, `"missing_duration"`, `"invalid_duration"`), odrzucając `NaN`, `Infinity`, `float`, wartości ujemne i brakujące pola.
  - W `hayhop.js` wynik końcowy wywołuje `config.endGame(score)` (wysyła `minigame_result` przez `minigames-api.js:1025`). Przekazanie `durationMs` do `HomeWindow.cs` jest poza zakresem PK-HH1/PK-HH2 (krok integracji).

## 5. Przypadki dla PK-T22
**JS (`tools/qa/ux-p130-hayhop.js` / `tools/qa/ux-p140-hayhop-adv.js`)**:
1. `HOP-hold-left-forever`: `step(16, { dir: -1 })` przez 200 kroków -> `state().pig.x >= 12` i `<= width - 12`, brak `NaN`.
2. `HOP-spam-restart-50`: 50 kolejnych wywołań `createGame` / restartu na stronie -> brak wycieku timerów/błędów, wynik resetuje się do `0`.
3. `HOP-resize-window`: zmiana rozmiaru okna Playwright (`420x640` -> `320x480` -> `600x800`) -> canvas pozostaje widoczny, brak błędów konsoli.
4. `HOP-pause-on-blur`: zdarzenie `blur` na `window` -> gra pauzuje (wysokość/czas nie rosną podczas pauzy).
5. `HOP-score-monotonic`: sekwencja 300 kroków skoku i spadania -> `score()` nigdy nie maleje między krokami.
6. `HOP-result-sent-once`: po spadku poniżej dolnej krawędzi `bridge.send` z `minigame_result` (lub `endGame`) wywołane dokładnie 1 raz, nawet po kolejnych 20 krokach `step`.
7. `HOP-console-clean`: 0 `console.error` i `pageerror` podczas ładowania, gry i restartu.

**C# (`tests/Cuy.Core.Tests/HayHopAdversarialTests.cs`)**:
8. `HOP-forged-score-zero-reward`: `HayHopReward.Compute(score: 500, durationMs: 2000, ...)` (250 pkt/s > 25 pkt/s) -> `Clovers == 0`, `Mood == 0`, `RejectedAsImpossible == true`.
9. `HOP-zero-time`: `HayHopReward.Compute(score: 100, durationMs: 0, ...)` -> `Clovers == 0`, `Rewarded == false`.
10. `HOP-daily-cap`: `dailyGamesCount == 10` lub `dailyCloversToday == 150` -> `Clovers == 0`, `Rewarded == false`; przy `dailyCloversToday == 145` i `score == 200` -> `Clovers == 5`.
11. `HOP-negative-and-nan`: `HayHopMessages.ValidateResultPayload` dla `score: -1`, `durationMs: -5`, `score: double.NaN` / float, `null`, brakujących pól -> zwraca niepusty kod błędu (nie `null`); `HayHopReward.Compute(-10, 5000, ...)` -> `Clovers == 0`.
12. `HOP-message-fuzz-300`: 300 losowych ładunków `JObject` (ziarno stałe) podanych do `ValidateResultPayload` i `MessageValidator` -> 0 nieobsłużonych wyjątków.
