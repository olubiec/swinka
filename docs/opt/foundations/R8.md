## 3. Risks

### 1. Save Migration and Schema Compatibility
- Risk: Changing `CareSettings.PigNames` from strings to objects could break existing save files (`%AppData%/Cuy/save.json`).
- Mitigation: Retain `public List<string> PigNames { get; set; }` in `CareSettings` (CareState.cs:30) and add `public List<CarePig> Pigs { get; set; } = new List<CarePig>();`. In `CareState.Normalize()` (CareState.cs:15-25), if `Pigs` is empty but `PigNames` has values, populate `Pigs` automatically with `new CarePig { Name = name }`. If `Pigs` has values, keep `PigNames` synchronized (`Pigs.Select(p => p.Name).ToList()`). Old saves load transparently without edits to `SaveSystem.Migrate()`.

### 2. Default `Enabled = false` vs Existing Unit Tests
- Risk: In `tests/Cuy.Core.Tests/CareScheduleTests.cs:37-40`, existing tests assert `Assert.True(CareSchedule.IsDue(_dailyTask, new CareSettings(), ...))` with an empty `CareSettings`. Modifying `IsDue` unconditionally would fail existing test assertions, violating AGENTS.md.
- Mitigation: Add `public bool CareManualReminders { get; set; } = false;` in `src/Cuy.Core/Balance.cs:10-60`. When false (default in unit tests), legacy `IsDue` behavior is preserved. When true (activated in `GameSession.Open` and `CalendarFeature`), tasks without explicit `Enabled = true` override are disabled. New tests in `CareReminderTests.cs` verify both behaviors without touching `CareScheduleTests.cs`.

### 3. Save Size Limits
- Risk: `WorldSaveSizeTests.cs:113-120` enforces total save size under 200 KB. `CareState.History` has a 120-day cutoff (Pet.Care.cs:98-99), but `CareState.Weights` has no retention limit.
- Mitigation: In `Pet.AddWeight` (Pet.Care.cs:118-132), cap weight history at 365 entries per pig. At ~45 bytes per entry, this adds at most ~16 KB, well below the 200 KB threshold.

### 4. Notification Mechanism and Popups
- Risk: Building a new notification popup mechanism.
- Grounding: Floating notifications already exist and work in `src/Cuy/dotNet/CareReminderForm.cs:1-70` and `CalendarFeature.cs:364-403` (`WS_EX_NOACTIVATE`, `WS_EX_TOPMOST`, idle check, auto-hide timer).
- Mitigation: Do NOT rewrite notifications. Wire `calendar_weight` so logging a weight calls `pet.MarkCareDone("weigh")` and closes `_currentReminder` if its task is `weigh`.

### 5. Tab and Retro Toggle Styling
- Risk: Broken image URLs in CSS. Per `web/home/style.css:1891`, CSS variables referencing pixel art (`var(--ui-tab_off)`, `var(--ui-tab_on)`, `var(--ui-panel_paper)`, `var(--ui-toggle_off)`, `var(--ui-toggle_on)`) resolve relative to `style.css`.
- Mitigation: Do not redefine background image URLs in `feature.css`. Apply global utility classes from `style.css` (`.room-tab`, `.ui-panel-paper`, `.retro-toggle`) directly in `feature.js` markup.

## 5. Proposed packages and decisions

### Proposed Package Split
Per `docs/PLAN_FAL_PRZEBUDOWA_11_11.md:83`, wave P8 is split into 3 packages:

1. **PK-P8a: Core Reminder Model, Pig Data, Message Validation & Host Wiring**
   - Covers: P8-01 and Core part of P8-02.
   - Adds `CarePig` (`Name`, `BirthDate`, `InitialWeightGrams`) to `CareSettings` with automatic sync to `PigNames`.
   - Adds `Balance.CareManualReminders` and updates `CareSchedule.IsDue` so reminders require opt-in when active.
   - Wires `Pet.AddWeight` to auto-complete the `weigh` task.
   - Updates `CalendarFeature.cs` to dismiss `_currentReminder` on weight input and expose structured pigs in state.
   - Creates `src/Cuy.Core/Input/Validation/CalendarMessages.cs` implementing `IMessageRuleSet`.
   - Adds unit tests in `tests/Cuy.Core.Tests/CareReminderTests.cs`.
   - Updates `docs/contracts/calendar.md`.

2. **PK-P8b: Calendar UI — Game-Style Tabs, Settings & Weight History**
   - Covers: P8-02 (UI), P8-03, and P8-04.
   - Creates `web/home/features/calendar/mock.js` registering handlers and mock state with `bridge`.
   - In `feature.js` and `feature.css`:
     - Style tabs with wood/paper aesthetic using `.room-tab` and `.ui-panel-paper`.
     - Settings tab: pig profile editor (name, birth/adoption date, initial weight) and manual reminder toggles using `.retro-toggle`, defaulting to unchecked.
     - Weight tab: full weight history table with delete actions; weight submission immediately closes due reminder and updates state.

3. **PK-P8q: Care Calendar Smoke Verification**
   - Creates `tools/qa/calendar-smoke.js` running in headless node/Playwright environment.
   - Verifies:
     1. Calendar renders with game-style wood/paper tabs.
     2. Adding a pig with birth date and initial weight persists into state.
     3. Reminders default to disabled until toggled on in Settings.
     4. Logging a weight updates the history table and clears due status on weigh task.

### Decisions for Owner
1. **Reminder default state vs test suite integrity**:
   - *Default Decision*: Reminders default to disabled (`enabled: false`) via `Balance.CareManualReminders = true` set in `GameSession.Open` and `CalendarFeature`. Bare unit tests retain legacy `IsDue` behavior, ensuring existing assertions in `CareScheduleTests.cs` remain 100% green without modification.
2. **Pig data backward compatibility**:
   - *Default Decision*: Store `Pigs: List<CarePig>` in `CareSettings` while keeping `PigNames` synced. Old saves load transparently, and `PigNames` are upgraded during `CareState.Normalize()`.
3. **Weight task completion rule**:
   - *Default Decision*: Logging a valid weight for any registered pig marks the weekly `weigh` task done for the current window and dismisses the desktop `CareReminderForm` popup.
4. **Weight history retention**:
   - *Default Decision*: Cap weight history at 365 entries per pig in `Pet.AddWeight` to guarantee saves remain under 200 KB (`WorldSaveSizeTests`).
5. **Tab styling**:
   - *Default Decision*: Use existing global 9-slice CSS classes from `web/home/style.css` (`.ui-panel-paper`, `.room-tab`, `.retro-toggle`) rather than duplicating custom background URLs in `feature.css`.
