## 2. Kontrakt `edit-history.js`, przyciąganie, komfort

Plik: `web/home/features/places/edit-history.js` (czysty UMD: `window.EditHistory`, `module.exports`, bez DOM/bridge).

### Operacje i odwrotności (`MAX_HISTORY = 50`)
- `place`: `{ kind: 'place', place, itemId, x, y, uid?: string|null }`
  - `forward`: `[{ type: 'room_place', place, itemId, x, y }]`
  - `inverse`: `[{ type: 'room_remove', place, uid }]` (`uid` uzupełniane przez `resolvePlacedUid` po odpowiedzi Core)
- `remove`: `{ kind: 'remove', place, uid, itemId, x, y, flip?: boolean }`
  - `forward`: `[{ type: 'room_remove', place, uid }]`
  - `inverse`: `[{ type: 'room_place', place, itemId, x, y }]` (+ `{ type: 'room_flip', place, uid }` po odzyskaniu `uid`, jeśli `flip === true`)
- `move`: `{ kind: 'move', place, uid, prevX, prevY, x, y }`
  - `forward`: `[{ type: 'room_move', place, uid, x, y }]`
  - `inverse`: `[{ type: 'room_move', place, uid, x: prevX, y: prevY }]`
- `flip`: `{ kind: 'flip', place, uid }`
  - `forward`: `[{ type: 'room_flip', place, uid }]`
  - `inverse`: `[{ type: 'room_flip', place, uid }]`

### API `window.EditHistory`
- `MAX_HISTORY = 50`
- `create(opts?)`: zwraca instancję `{ push, resolvePlacedUid, undo, redo, acknowledge, rollbackPending, clear, counts }`:
  - `push(op)`: dodaje wpis na stos `undo`, czyści `redo`, przycina najstarszy gdy `length > maxSteps`.
  - `resolvePlacedUid(place, itemId, x, y, uid)`: uzupełnia brakujące `uid` w ostatnim pasującym wpisie `place` po otrzymaniu stanu z Core.
  - `undo()` / `redo()`: przenosi wpis między stosami, ustawia `_pending = { dir, entry }` i zwraca tablicę wiadomości do `bridge.send(...)` (zwraca `[]` gdy stos pusty lub brak `uid` dla `room_remove`).
  - `acknowledge()`: czyści `_pending` po zmianie układu w `render(state)`.
  - `rollbackPending()`: gdy Core odrzuci wiadomość (kolizja, `owned === 0`, toast błędu lub brak zmiany układu), cofa wpis do poprzedniego stosu i zwraca `true`.
  - `clear()`: zeruje `undo`, `redo`, `_pending`; wywoływane przy zmianie sceny (`edit-panel.js:2074-2097`, `render` `:1949-1951`).
  - `counts()`: `{ undo: number, redo: number, canUndo: boolean, canRedo: boolean }`.
- `snapCell(sceneKind, itemDef, px, py, metrics)`: czysta funkcja przyciągania zgodna z `edit-panel.js:93-136` (`metrics = { cellSize: 16, floorY0: 32, cols: 16 }`), zwraca `{ x, y, cx, cy, cw, ch, off }`.
- `computeComfortDisplay(roomsState, sceneId)`: czyta `rooms.comfort` (`rooms.comfort[sceneId]` lub `rooms.comfort`, pola `{ score, cap, moodFactor }` wg `W20-03:9`, domyślnie `0, 100, 1`), wylicza `moodPct = moodFactor <= 1 ? Math.round((1 - moodFactor) * 100) : Math.round(moodFactor)`, zwraca `{ score, cap, moodFactor, moodPct, ratio, text: 'Comfort ' + score + '/' + cap + ' - mood drops ' + moodPct + '% slower' }`.

## 3. Kontrakt `draw-budget.js` i dane

Dane: `assets/data/draw_limits.json`:
```json
{
  "maxItems": 48,
  "maxAnimated": 24,
  "maxParticles": 32,
  "maxLights": 8,
  "hiddenFps": 30,
  "activeFps": 60,
  "cullMarginPx": 32,
  "layerPriority": { "fixture": 0, "wall": 1, "floor": 2, "ground": 3, "decor": 4 }
}
```
Moduł: `web/home/lib/draw-budget.js` (czysty UMD: `window.DrawBudget`, `module.exports`):
- `DEFAULT_LIMITS`: stała równa powyższemu JSON.
- `loadLimits(url?)` / `setLimits(obj)` / `getLimits()`: asynchroniczny odczyt JSON przez `fetch` + wstrzykiwanie w testach.
- `isVisible(thing, viewport, marginPx?)`: sprawdza przecięcie AABB `(x, y, w, h, anchorX, anchorY)` z `{ x: 0, y: 0, width, height }` powiększonym o `cullMarginPx` (`32`).
- `selectItems(items, viewport, focusPt?, limits?)`: filtruje przez `isVisible`; powyżej `maxItems` (`48`) degraduje najdalsze ozdoby (`decor`, potem `ground` wg `layerPriority` i dystansu do `focusPt`), zachowując `fixture` i `isGhost`.
- `capAnimated(items, focusPt?, limits?)`: zwraca `Set` do `maxAnimated` (`24` wg `W21-05:9`) najbliższych obiektów wieloklatkowych/świecących; pozostałe rysują klatkę `0`.
- `capParticles(particles, limits?)`: ogranicza do `particles.slice(-maxParticles)` (`32`).
- `capLights(sources, focusPt?, limits?)`: zwraca do `maxLights` (`8`) najbliższych włączonych źródeł (`s.on !== false`).
- `shouldDrawFrame(nowMs, lastFrameMs, isHidden, limits?)`: dla `isHidden === true` wymusza interwał `1000 / hiddenFps` (`33.33 ms` = `30 fps`), zwraca `{ draw: boolean, minIntervalMs: number }`.
- `frameCost(stats, limits?)`: z `{ items, animated, particles, lights }` zwraca `{ items, animated, particles, lights, score, overBudget }`, gdzie `score = Math.round((items/maxItems)*40 + (animated/maxAnimated)*25 + (particles/maxParticles)*15 + (lights/maxLights)*20)`.

## 5. Rezydenci w edytorze

Tryb podglądu w `edit-panel.js` + `canvas-pig.js` (zero `bridge.send`, bez wpływu na `GameState`):
1. **Przełącznik**: przycisk `id="editResidentsBtn"` (`Residents`, `aria-pressed`) w `edit-drawer-header-actions` (`edit-panel.js:1674`), lokalna flaga `_showResidents = true`, metody `CuyEdit.getShowResidents()` / `setShowResidents(bool)`.
2. **Limit i ukrywanie**: `canvas-pig.js:1298` (`getPigEntries`) przy `isEditMode() && !CuyEdit.getShowResidents()` zwraca `[]`; przy włączonym podglądzie limit `MAX_RESIDENTS = 6` (`W27-07:9`).
3. **Unikanie mebli i spoczynek**: `inst.rebuildGrid()` (`edit-panel.js:756,784`) + `enforceFreePigs` (`canvas-pig.js:1331-1338,3044`) omijają nowo postawione meble. Śpiące świnki kierują się obok `cushion_big`, `cosy_nook`, `sig_*` lub najbliższego rogu.
4. **Reduced motion**: gdy `matchMedia('(prefers-reduced-motion: reduce)').matches` w trybie edycji, `update(dt)` pomija krok ruchu (`scenePigs.step`) i zostawia klatkę `idle`.
5. **Kliknięcie świnki w edycji**: w `canvas-pig.js:2792-2793` (`handleCanvasClick`), gdy `this.isEditMode()` jest `true`, kliknięcie świnki NIE wywołuje `this.pet()` (brak `{ type: 'pet' }`), lecz wysyła na `document`: `new CustomEvent('room-pig', { detail: { pigId } })`.
